# 验证方法目录：21 类

分类参考：[代码验证全景图](https://kejun.github.io/code-verification-atlas/)。保留 S01–S06、D01–D11、X01–X04 标识，以便报告和后续审计逐项对照。

这是方法目录，不是所有项目必须全部完成的发布清单。按实际语言、架构、用户承诺和风险判断适用性；某工具只是实现该方法的一种选择。先看测试的真实依赖、执行边界和断言，再分类，不按文件后缀、运行器名称或工具品牌计数。

## 静态验证

| ID | 方法 | 查什么证据 | 范围与常见误判 |
| --- | --- | --- | --- |
| S01 | 类型检查 | 编译器配置、检查范围、严格选项、实际命令、退出码和版本 | 区分仅转译与类型检查；依赖被排除或存在大量忽略项时注明。类型通过不能证明业务目标正确。 |
| S02 | 语法检查 | 解析器/编译器结果，实际包含的源文件及构建入口 | 编译器可同时检查类型和语法；无需重复跑另一工具凑项。未导入、未构建的源码不自动获得覆盖。 |
| S03 | 基础语义检查 | 变量定义、作用域、签名匹配等语言规则的检查设置与结果 | 指语言层面的语义；不能把它扩张为需求理解、金额计算或其他业务语义已正确。 |
| S04 | 静态分析 | Lint、格式、复杂度、异味、数据/控制流、不可达路径和依赖分析报告 | 分别列出实际启用的子类。编译器有部分流分析，不等于已完成专项安全、复杂度或循环依赖检查。 |
| S05 | 安全静态扫描 SAST | 扫描器规则集、路径、严重度、抑制项、密钥扫描结果及修复/接受记录 | 工具存在不代表已扫描。SAST、依赖漏洞 SCA、渗透测试和沙箱边界测试是不同证据；不要互相替代。 |
| S06 | 形式化验证 | 模型/性质/边界/公平性、完整完成日志、反例、源码对应、版本绑定及独立读回 | 区分模型检验、定理证明、抽象解释、静态契约证明。有限模型穷举只覆盖该域；每边代表前缀回放不是全部实现历史的 refinement/bisimulation 证明。新行为未进入模型时单列未覆盖范围，按风险与所需保证决定是否补切片，不强制所有分支形式化。 |

契约可静态证明，也可运行时检查。S06 的静态契约证明和 D08 的运行时断言应按实际证据分别描述。形式化方法之间是可选技术路线，未采用定理证明不自动说明已有模型检验不成熟。

## 动态验证

| ID | 方法 | 查什么证据 | 范围与常见误判 |
| --- | --- | --- | --- |
| D01 | 单元测试 | 独立可控边界内的函数/模块行为、依赖替身、具体断言及实际结果 | 混合 Vitest/pytest 用例不能一概叫单元测试。真实数据库、网络、进程和文件系统接线归入对应层。独立单测套件为空时，核查纯行为是否已由场景驱动承接，不机械新增重复测试。 |
| D02 | 集成测试 | API、数据库、队列、进程、文件系统、服务适配器等真实接线及隔离夹具 | 明确哪些组件真实、哪些模拟；本地 SQLite 成功不证明另一种数据库或远端服务集成成功。 |
| D03 | 端到端测试 | 用户操作/外部入口到系统结果的完整路径、浏览器/客户端、真实服务与持久化结果 | 明确运行环境及替换边界。浏览器和 CLI 真实但模型/支付方受控时，只能证明该系统路径，不能证明真实供应商效果。 |
| D04 | 契约测试 | 请求/响应、事件/消息、Schema、兼容性、错误语义及消费方/提供方对应检查 | 不强制使用 Pact。Schema 文件存在只证明契约已声明；静态接口签名不证明远端提供方遵守协议。EARS/Gherkin 是需求和验收表达，不能单独替代接口运行证据。 |
| D05 | 属性测试 | 输入/事件生成器、性质、不变量、范围、样本/种子、失败缩减和复现方式 | 区分固定样例、有限顺序枚举、模型驱动生成和随机属性测试。有界枚举有价值，但不声称随机空间或任意事件历史均已覆盖。 |
| D06 | 模糊测试 Fuzz | 目标入口、输入生成/变异方式、语料、运行预算、崩溃/异常判据和最小复现 | 一组畸形输入用例不是持续 Fuzz。除崩溃外，协议错误、资源耗尽、挂起、异常授权和不可恢复状态也可能是相关判据。 |
| D07 | 变异测试 | 变异算子/故障点、真实被改坏源码、被测断言、预期失败、原版恢复及结果 | 定向负对照和故障注入属于有效检出证据；未覆盖全部算子时不宣称全量 mutation score。编译失败、导入错误或无关超时不算目标缺陷被检出；模型变异不能替代真实源码对照。 |
| D08 | 运行时检查 | 边界校验、Schema、类型守卫、前后置条件、断言、权限/额度/版本守卫及拒绝路径 | 区分测试专用断言与生产运行时守卫。成功路径通过不证明拒绝、失效、取消、恢复和并发顺序均已检查。 |
| D09 | 动态安全测试 DAST | 对运行中应用的外部探测、规则/攻击面、目标环境、发现项与复验 | 授权、沙箱、文件/网络边界测试可作专项安全证据，但不等于完整 DAST 或渗透测试。测试生产目标、攻击外部服务和真实凭据须遵循实际授权。 |
| D10 | 性能测试 | 基准/负载/压力/长稳、并发和数据规模、延迟/吞吐/资源、基线与环境 | 区分合成延迟样例、真实服务测量和改动前后配对实验。功能期限/超时守卫不是性能基准；一个快速用例不能证明无泄漏或长期稳定。 |
| D11 | 内存安全验证 | ASan/LSan/UBSan/TSan 等实际结果、原生组件范围、泄漏与竞争复现 | 根据语言判断适用性。TS/JS 层不直接适用的消毒器可注明原因；存在原生扩展时不能把整个系统标为不适用。JS 资源泄漏/长稳可在 D10 单独审计。 |

对故障恢复另查：进程退出/崩溃、事务回滚、消息重放、取消、过期、未知外部效果和重启后的状态。进程被杀后的恢复测试不自动证明磁盘断电可靠性；拒绝下一次调用不代表撤回了已经发生的副作用。

## 跨方法维度

| ID | 维度 | 查什么证据 | 范围与常见误判 |
| --- | --- | --- | --- |
| X01 | 覆盖率 | 语句/分支/条件/路径/MC/DC 的类型、采集范围、分母、排除项与报告 | 规格绑定/场景执行覆盖、代码覆盖、模型状态覆盖是不同指标。测试通过数不是覆盖率；未采集写“未测量”，不写成 0%。高代码覆盖不证明断言有检出力。 |
| X02 | 可维护性 | 代码审查、文档、可复现命令、复杂度/依赖治理、SCA 和责任维护机制 | 区分代理复核与人工批准。文档齐全不代表其内容已执行；SCA 结果说明直接/间接依赖、漏洞库时间和接受项。 |
| X03 | 合规性 | 许可证清单/策略、归属声明、适用编码标准、例外与结果 | 依据项目分发方式、行业和合同判断；使用开源库不等于做过许可证检查。MISRA/AUTOSAR 等标准不适用时给出技术理由。 |
| X04 | AI/ML 验证 | 输出/工具 Schema、任务集、真实模型/数据版本、判据、基线、重试/种子、质量/成本/时延与鲁棒性结果 | 预排回复只证明接线。真实模型评估应区分工具选择、参数正确、纠错、目标达成、幻觉、权限遵守及提示注入等相关风险；不是每项都适用于所有 AI 功能。涉及训练/分类/决策时再审计数据漂移、公平性等。 |

## 逐项取证规则

每个结论至少关联：范围/用户承诺、适用性、源码或配置位置、执行命令/工作流、实际版本、结果和原始证据位置。没有执行记录时，只记录已发现的检查能力；没有找到检查时，先说明搜索范围。

同一项检查可以支持多个维度，但不得重复累加为“验证次数”或成熟度分数。每条结果声明其模拟、环境、数据规模、有限边界、排除项和未证明内容。

检查真实 CI/脚本是否执行了预期测试，是否允许空集合、跳过失败、条件跳过或仅验证编译。旧报告有用，但必须检查其覆盖文件及行为是否适用于当前目标版本；指纹相同只支持身份对应，不单独证明行为正确。

优先级使用 [成熟度与风险规则](rubric.md)。对关键用户承诺，需要指出缺失的证据链，而非只列出没安装的工具。共享可复用的现有场景、模型驱动和夹具，遵守被审计项目关于测试分层和新增测试的规则。
