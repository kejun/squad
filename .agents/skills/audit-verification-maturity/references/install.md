# 安装、触发与作用域

这是通用 Agent Skills 目录，不依赖 squad 的源码、账户、测试数量或某个模型提供方。依据 [Agent Skills 规范](https://agentskills.io/specification) 组织，可离线读取随包参考文件。

## 项目级使用

将整个 `audit-verification-maturity/` 目录复制到目标项目的 `.agents/skills/`。在支持该约定的宿主中由技能发现机制加载；在会读取 AGENTS.md 的代理中，可加入以下路由：

> 当用户在代码项目语境说「审计验证怎么做的」「验证层成熟度」「哪些验证做了、还缺什么」或显式使用 `$audit-verification-maturity` 时，先读取 `.agents/skills/audit-verification-maturity/SKILL.md`，按证据检查缺口并给出建议。不要仅凭测试总数或CI摘要判断充分性。

项目副本和这条路由已接入当前 squad 仓库。仓库规则只作用于读取该仓库的后续工作；安装包本身不会向宿主全局技能目录注册，也不会改变本对话的系统工具列表。其他项目需复制/安装，或按其宿主支持的用户级技能目录配置。

## 在 Squad Bot 运行时使用

Squad服务默认扫描运行账号的 `~/.agents/skills/`，不自动扫描克隆项目。若希望由其Bot发现本技能，应由宿主维护者按本机部署约定安装到该账号的受信技能根，或配置 `SQUAD_LOCAL_SKILLS_ROOTS` 后重启。本交付没有修改全局目录、服务账号配置或运行时扫描逻辑。

## 调用示例

- 「审计验证怎么做的，看看这个项目还缺什么。」
- 「审计这个PR的验证层成熟度，区分已跑和只配置了的检查。」
- 「按代码验证图谱检查缺口，给最值得补的三项建议。」
- 「`$audit-verification-maturity` 审计当前仓库。」

「验证码验证怎么做」「解释形式化验证的概念」「只运行 npm test」不是全面审计触发。用户也要求审计时再覆盖对应范围。

## 更新与核查

整体更新目录，保持frontmatter名称、目录名和相对引用一致。更新方法或触发条件后，用 evaluation.md 重新核查，并分别记录格式验证、代理语义评估和宿主真实发现结果。通过样例不代表所有未来表达均能自动命中；没有宿主注册证据时不能声称全局安装成功。
