# 长期执行经验的模式匹配与失效处理

2026 年 11 月 23 日评估草案。核查基线为 Squad 主分支 `7e86ef7`。现行验收以 BT_Y181–Y189 为准。拟议条目供下一轮迭代评审。 [长期执行经验](long-term-experience.md) · [验收场景](../../features/80_long_term_experience.feature)

## 评估结论

**先让可信回执入库，再启用跨文档建议。** 当前读取路线已按 URL 的 origin 匹配。下一轮的价值在于独立保存失败事实、成功路线和已发布分片，并用已知的读取意图、访问范围、执行环境和读取器约束建议的适用范围。同域新文档可尝试已验证的读取路线，正文身份和完整性由各文档的本轮回执证明。修复登录识别、登记可信读取器和建立分片来源映射，可以改善现有双回执入库。仅出现失败或仅取得正文的任务还需要独立的入库条件。 [当前路线匹配](../../src/task/execution-memory.ts#L64)

### 代码核查

- **发布与记账。** 终态提交先登记待处理发布。收集器即使跳过路线学习，仍会写入 `processed`，维护事务随后删除待处理项。目录必须在任务开始时可用，并与处理时的全量目录一致。路线还需要同一资源先有可信网页登录失败，再有完整 CLI 正文回执，以及目录中的命令、运行环境和域名声明。自动发现目录可提供安装信息，服务用途和正文契约仍需要可信登记。 [发布维护](../../src/engine.ts#L184) · [入库条件](../../src/execution-memory.ts#L39) · [记账](../../src/execution-memory.ts#L106) · [自动目录](../../src/automatic-cli-catalog.ts#L181)
- **网页和 CLI 证据。** 网页回执已有目标 URL、最终 URL、重定向和状态等宿主证据。现有登录识别主要匹配正文文本。应使用受控页面和宿主捕获的登录特征，区分 HTTP 200 登录页、合法正文中的「登录」字样及普通重定向。CLI 已支持静态读取器配置。现有通用 JSON 读取器匹配 ID 或 slug，`complete` 取自进程输出的截断标记。语雀需要另行确认请求 URL 与书库及文档标识的绑定，以及该命令的响应何时代表完整正文。 [网页回执](../../src/runner.ts#L307) · [登录识别](../../src/resource-acquisition.ts#L76) · [CLI 读取器](../../src/acquisition-readers.ts#L122) · [静态配置入口](../../README.md#L66)
- **分片来源。** `Goal.partitionResources` 可接收明确的来源映射。普通输入的规划协议只有分片 ID、目标和预期产出，当前回退从目标和产出里的 URL 反查任务来源。模型改写或省略链接时，即使分片报告成功，也可能没有可匹配的索引项。对普通多文档任务，建议让规划从本轮已解析的来源中选取引用，并由宿主校验引用与分片的对应关系。 [规划协议](../../src/input-intent.ts#L5) · [来源映射](../../src/task/map-scheduling.ts#L23) · [索引门槛](../../src/execution-memory.ts#L84)
- **失效范围。** 现有逻辑取一次 Work 最新的相关回执。可信登录失败或资源不符可停止本批推广，并在终态按路线 ID 和版本停用。持久化路线使用整体的 `disabled` 和计数，原始失败引用来自建路时的观察。应让新反证携带自己的回执引用和已验证范围，并防止后续结果覆盖已触发的停用。 [当前推广与回退](../../src/task/execution-memory.ts#L71) · [持久化反馈](../../src/execution-memory.ts#L68)

## 拟议需求（EARS）

沿用打开长期经验时的同会话作用域。本草案建议在发布处理时建立新索引，运行时回执继续随原 Work 持久化。已采用路线的可信反证沿现有终态处理路径登记，即使采用后用户停止任务。 [现有发布和反馈门槛](../../src/execution-memory.ts#L19)

| 编号 | 拟议要求 | 可观察验收 |
| --- | --- | --- |
| MEM-06 | 当任务发布且存在可信的网页登录或沙箱执行边界回执时，系统应分别保存可追溯的失败观察。观察的范围应由回执支持，缺少替代路线的成功证据时也可保存。 | 只触发登录、只触发沙箱权限错误时，分别查到来源回执。错误文档和普通 HTTP 200 正文无法作为登录观察。 |
| MEM-07 | 当已发布任务中的专用读取器证明目标文档身份、非空正文和完整性，且原调用的相关工具及环境可追溯时，系统应保存成功路线。 | 只有可信 CLI 成功的任务可入库。进程退出零、书库不符、截断、分页未完成或验证器未知时，正文状态仍显示相应缺口。 |
| MEM-08 | 当系统处理同一发布版本时，应逐项记录观察、路线和分片索引的处理结果及缺口原因。若相关信息可从原有可信记录补足，应允许重试并对同一证据去重。 | 模拟目录不可用、事务故障和重启。原发布持续可读，可补证的项目只产生一次有效记录。缺少可核对原始绑定的项目留下明确原因。 |
| MEM-09 | 当已发布成功分片能唯一关联一个源且原 Work 的当前尝试有匹配正文回执时，系统应保存原来源及结果的索引。只有当前请求固定相同来源身份、正文 SHA-256 和提取要求时，系统才应直接交回原产物及引用。 | 普通多文档请求可核对分片的来源绑定。映射缺失或冲突、要求刷新、正文版本缺失或任一匹配条件变化时，对受影响分片执行普通读取或提取。 |
| MEM-10 | 当新任务在同会话内的读取意图、来源范围、相关工具契约、环境及访问条件均与已验证路线相符时，系统应先向一个适用分片给出建议。首个分片取得本轮可信正文后，系统才应向本批其他适用分片推荐这条路线。 | 同域另一篇文档可先试用。无关目录条目变更后仍可匹配。每篇新文档按本轮审批和正文回执结算，旧建议仅引用历史事实。 |
| MEM-11 | 如果匹配条件改变或无法核实，系统应走普通路径。如果采用后只有超时、限流或回执缺失，系统应暂停该批推广，由原重试和备选路径处理。 | 切换账号、成员权限或相关工具，以及注入暂时异常。原范围的历史路线仍可供后续适用任务核验。 |
| MEM-12 | 当已采用的路线收到可核对的同范围反证时，系统应立即停止向受影响分片推广，并持久化对应范围、路线版本及反证引用，即使任务随后停止。 | 单篇文档访问变化只影响该文档。可信的工具或认证范围失效停用对应范围。普通调度可继续，旧尝试或旧版本的迟到结果无法改写新版本。 |
| MEM-13 | 当普通路径在对应范围内取得晚于反证的可信成功证据时，系统应登记新版本并供后续任务重新验证。 | 通过原权限完成独立复验后恢复建议。单篇成功只恢复其已证实的适用范围。 |
| MEM-14 | 当在同一资料快照及等价账号、工具和初始历史上做开关对照时，系统应提供覆盖和来源核对、匹配与执行结果，以及工具、模型和耗时记录。 | 可分别统计候选命中、实际采用、正文验证成功、误匹配、重复探测、工具调用、模型请求、Token 和墙钟。关闭时按普通路径执行。 |

核查。MEM-06–09 对应原讨论的「能沉淀」和固定版本结果，扩展 MEM-01 的入库条件并保留 MEM-04 的严格匹配。MEM-10–11 对应「能迁移」，沿用 MEM-02 的单分片试用，将 BT_Y184 的目录变化细化为相关条目变化。MEM-12–13 对应「能回退和恢复」，补齐 MEM-03 的证据范围和恢复版本。MEM-14 对应「能量化收益」及 MEM-05。响应以回执、索引、队列和发布结果核对。语雀完整性信号和可用于比较的认证范围仍需取证，未知时走普通路径。

## 实施顺序与验收

1. **先验证语雀入库。** 从脱敏的网页和 CLI 样本建立正反例，核对同一书库内的文档、不同书库的同名 slug、登录页、正文截断和未知完整性。用宿主路径形成证据，保留本轮审批要求。沙箱的 `/bin/ps` 观察须关联已结算的受控操作及已知 CLI 调用，间接执行只在能核实两者关系时纳入。走普通多文档入口确认来源映射、发布写入及重启补记。以可以查到独立观察、可信路线、匹配分片及各自缺口原因作为进入下一阶段的条件。
2. **再验证结构化迁移和回退。** 用 `ToolExperience` 的条件、行动、预期结果及证据字段投影建议。已知访问范围内的网页登录观察可提醒避开重复探测。沙箱观察仅适用于相同工具和执行边界。路线匹配复用已有 CLI 条目版本，再核对实际可执行工具、运行环境、读取器版本、输入输出契约和非秘密访问范围。目录元数据可在实际调用时绑定，取不到原调用身份的旧记录保留缺口。整套工具协议继续用于校验任务和执行回执。 [现有建议投影](../../src/task/tool-experience.ts#L110) · [CLI 条目版本](../../src/tool-inventory.ts#L44)
3. **按两种收益做对照。** 路线组以同一份历史分别开关，选择未出现的同域文档，包含同域公开文档、不同访问范围和暂时异常。先对照每篇回执、交付覆盖、来源和授权，再比较重复登录探测、帮助探测与沙箱失败。固定版本组使用同一份已发布索引，加入版本变化和刷新项，对比分片派发、模型请求和 Token。记录每轮墙钟、各次调用时长与并发情况，分别报告候选命中、实际采用和正文通过的分母。 [现有固定版本验收](../../features/80_long_term_experience.feature#L53) · [执行测量](../../README.md#L257)
