# 长期执行经验的模式匹配与失效处理

2026 年 11 月 23 日评估草案。核查基线为 Squad 主分支 `7e86ef7`。实现按 BT_Y181–Y201 验收。下文保留提出方案时的基线核查和需求依据。 [长期执行经验](long-term-experience.md) · [验收场景](../../features/80_long_term_experience.feature)

## 模式匹配评估

**建议采用结构化匹配。** 现有方案已经能把读取路线迁移到同源新文档。新方案的价值是识别哪些文档适用，以及让无关目录变更后的有效路线继续命中。以同会话、读取意图和规范化来源召回候选，再依据各条经验的实际适用条件决定给出提示、优先试用或走普通路径。来源域是查找线索。相同域名下的公开文档、不同书库和单篇共享例外都要按当前来源核对。 [现有来源匹配](../../src/task/execution-memory.ts#L64) · [现有目录与排序](../../src/execution-memory.ts#L125)

用相同的历史路线做受控对照，两篇此前未见、可直接用网页读取的同源文档，在普通路径下均通过网页读取。开启现有经验后，两篇都采用了 CLI 路线，首个回执前只派发一篇。只新增一个无关目录条目，读取器的条目版本保持相同，两篇都恢复为普通路径。这个对照使用受控文档、真实 SQLite 和原 Runner，可以复核匹配范围及全目录依赖。 [集成夹具](../../tests/long-term-experience-acceptance.ts) · [分片派发](../../src/task/map-queue.ts#L13)

| 观察或候选 | 适用条件 | 命中后的行动 |
| --- | --- | --- |
| 网页曾返回登录页 | 读取目标明确，当前目标有证据属于相同访问范围，且本次网页仍采用同一无登录态入口。可用已确认的服务访问规则或本轮回执判断范围。 | 提示避开同条件下的匿名探测。如果只知道同域及某个旧链接要求登录，当前文档仍走普通路径。 |
| 沙箱内的语雀读取调用触发 `/bin/ps` 权限错误 | 已结算回执能把错误归因于同一种读取调用、同一工具和相同的实际沙箱约束。确认失败发生在访问文档前，或有证据表明该失败与目标文档无关。 | 提示避开该失败变体。宿主侧读取是否可尝试，由当前工具、认证范围及审批单独决定。 |
| 语雀宿主读取路线已取得可信正文 | 当前任务需要读取文档，目标落在已确认的服务和访问范围内，账号、执行环境、相关工具及读取器输入输出契约可核对。 | 先推荐给一个适用分片，按本轮流程申请许可并校验原文。成功后才推荐给本批仍待处理的适用分片。 |
| 已发布分片 | 来源身份、正文 SHA-256、提取要求一致，且请求明确使用固定版本。 | 直接交回原产物及其来源引用。 |

**失败类型描述已见的现象。** 可以在首次调用前召回历史观察。有足够依据证明当前条件相同时才建议跳过。要求本轮先出现同样的失败会保留第一次重复探测。五轮的登录样本支持保存该现象。判断它能否迁移，还需要同域公开文档及不同访问范围的对照。沙箱现象的适用范围由执行约束决定，网页登录现象的适用范围由文档访问条件决定。

**使用现有 `ToolExperience` 展示建议。** 宿主用可核对字段做判定，描述用于解释命中原因。首版可复用 CLI 条目版本定位相关工具，再核对实际执行变体、读取器和协议。条目版本只反映登记元数据。当前工具就绪信息也只有认证状态，缺少可比较的账号身份。无法取得可信、非秘密的账号或访问范围标识时，宿主路线只作为诊断提示，普通调度继续。多个已适用的候选优先选择更具体的范围，同范围比较最近的可信验证。证据冲突且无法判定时走普通路径。 [建议投影](../../src/task/tool-experience.ts#L110) · [条目版本](../../src/tool-inventory.ts#L44) · [工具就绪](../../src/cli-readiness.ts#L44)

**试用按已确认的适用范围进行。** 首个分片的可信成功开放同范围建议，其他文档仍逐份校验。只有候选或条件未知的分片照常派发。现有调度会让匹配同一路线的分片等待首个回执。如果继续使用同范围等待，对照需测量等待成本及超时后的恢复，避免节省工具调用的同时拖慢交付。单篇登录失败或返回错误文档时撤下受影响分片的建议。只有对相同账号范围或工具环境有独立反证时，才扩大停用范围。超时、限流和回执缺失走现有重试，保留路线。 [推广条件](../../src/task/execution-memory.ts#L94) · [当前等待逻辑](../../src/task/map-queue.ts#L13)

首版的已知模式可用 SQLite 和结构化规则表达。AgentCore 支持保留单次经历并归纳关联经验，LangGraph 支持命名空间内检索，Agent Skills 支持按相关性加载具体用法。随着候选增多，可以比较语义排序对召回的帮助，实际适用性仍以相同的结构化条件核对。 [AgentCore Episodic Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/episodic-memory-strategy.html) · [LangGraph Memory Store](https://docs.langchain.com/oss/python/concepts/memory#memory-storage) · [Agent Skills Progressive Disclosure](https://agentskills.io/specification#progressive-disclosure)

## 如何判定新方案更好

使用相同的历史回执、文档快照、账号、工具环境和模型，分别跑普通流程、现有同源加全目录匹配、拟议结构化匹配。路线组使用未见过的文档和无固定正文哈希的请求。用受控的同批任务看候选、建议、采用、可信正文和回退，再到真实审批路径做开关对照。BT_Y182 的夹具在试用轮重用建路时的 URL。这里用未见文档验证适用范围。 [现有路线试用场景](../../features/80_long_term_experience.feature#L20) · [场景绑定](../../tests/bdd/long-term-experience.steps.ts#L79) · [执行测量](../../README.md#L257)

| 对照样本 | 通过条件 |
| --- | --- |
| 同一已知访问范围内的新文档 | 保留有效迁移。首份按原授权通过，后续建议只发给已确认适用的分片。 |
| 同域公开文档、访问条件未知、账号或权限变化 | 可用的普通读取没有被跳过，也没有由于候选命中额外请求宿主审批。 |
| 无关工具变化、相关读取器或沙箱环境变化 | 无关变更保留有效建议。相关条件变化后走普通路径。 |
| 单篇失权、明确的认证范围失效、暂时异常 | 停用范围与反证一致。暂时异常后普通调度继续。 |
| 相同沙箱边界的失败、不同环境或归因不确定的同名错误 | 已知条件下减少重复调用。其他情况走普通路径，保留诊断依据。 |

先核对文档覆盖、准确来源、审批和回退，再比较误推荐、漏推荐、跳过有效网页路径、重复探测、额外审批、分片等待、工具调用、模型请求、Token 和墙钟。固定版本分片另跑开关对照，以免把复用产物节省的时间计入路线匹配收益。 [现有固定版本实测](https://github.com/kejun/squad/pull/78)

### 代码核查

- **发布与记账。** 终态提交先登记待处理发布。收集器即使跳过路线学习，仍会写入 `processed`，维护事务随后删除待处理项。目录必须在任务开始时可用，并与处理时的全量目录一致。路线还需要同一资源先有可信网页登录失败，再有完整 CLI 正文回执，以及目录中的命令、运行环境和域名声明。自动发现目录可提供安装信息，服务用途和正文契约仍需要可信登记。 [发布维护](../../src/engine.ts#L184) · [入库条件](../../src/execution-memory.ts#L39) · [记账](../../src/execution-memory.ts#L106) · [自动目录](../../src/automatic-cli-catalog.ts#L181)
- **网页和 CLI 证据。** 网页回执已有目标 URL、最终 URL、重定向和状态等宿主证据。现有登录识别主要匹配正文文本。应使用受控页面和宿主捕获的登录特征，区分 HTTP 200 登录页、合法正文中的「登录」字样及普通重定向。CLI 已支持静态读取器配置。现有通用 JSON 读取器匹配 ID 或 slug，`complete` 取自进程输出的截断标记。语雀需要另行确认请求 URL 与书库及文档标识的绑定，以及该命令的响应何时代表完整正文。 [网页回执](../../src/runner.ts#L307) · [登录识别](../../src/resource-acquisition.ts#L76) · [CLI 读取器](../../src/acquisition-readers.ts#L122) · [静态配置入口](../../README.md#L66)
- **分片来源。** `Goal.partitionResources` 可接收明确的来源映射。普通输入的规划协议只有分片 ID、目标和预期产出，当前回退从目标和产出里的 URL 反查任务来源。模型改写或省略链接时，即使分片报告成功，也可能没有可匹配的索引项。对普通多文档任务，建议让规划从本轮已解析的来源中选取引用，并由宿主校验引用与分片的对应关系。 [规划协议](../../src/input-intent.ts#L5) · [来源映射](../../src/task/map-scheduling.ts#L23) · [索引门槛](../../src/execution-memory.ts#L84)
- **失效范围。** 现有逻辑取一次 Work 最新的相关回执。可信登录失败或资源不符可停止本批推广，并在终态按路线 ID 和版本停用。持久化路线使用整体的 `disabled` 和计数，原始失败引用来自建路时的观察。应让新反证携带自己的回执引用和已验证范围，并防止后续结果覆盖已触发的停用。 [当前推广与回退](../../src/task/execution-memory.ts#L71) · [持久化反馈](../../src/execution-memory.ts#L68)

## 需求（EARS）

沿用打开长期经验时的同会话作用域。发布处理建立新索引，运行时回执继续随原 Work 持久化。已采用路线的可信反证沿现有终态处理路径登记，即使采用后用户停止任务。 [现有发布和反馈门槛](../../src/execution-memory.ts#L19)

| 编号 | 拟议要求 | 可观察验收 |
| --- | --- | --- |
| MEM-06 | 当任务发布且存在可信的网页登录或沙箱执行边界回执时，系统应分别保存可追溯的失败观察。观察的范围应由回执支持，缺少替代路线的成功证据时也可保存。 | 只触发登录、只触发沙箱权限错误时，分别查到来源回执。错误文档和普通 HTTP 200 正文无法作为登录观察。 |
| MEM-07 | 当已发布任务中的专用读取器证明目标文档身份、非空正文和完整性，且原调用的相关工具及环境可追溯时，系统应保存成功路线。 | 只有可信 CLI 成功的任务可入库。进程退出零、书库不符、截断、分页未完成或验证器未知时，正文状态仍显示相应缺口。 |
| MEM-08 | 当系统处理同一发布版本时，应逐项记录观察、路线和分片索引的处理结果及缺口原因。若相关信息可从原有可信记录补足，应允许重试并对同一证据去重。 | 模拟目录不可用、事务故障和重启。原发布持续可读，可补证的项目只产生一次有效记录。缺少可核对原始绑定的项目留下明确原因。 |
| MEM-09 | 当已发布成功分片能唯一关联一个源且原 Work 的当前尝试有匹配正文回执时，系统应保存原来源及结果的索引。只有当前请求固定相同来源身份、正文 SHA-256 和提取要求时，系统才应直接交回原产物及引用。 | 普通多文档请求可核对分片的来源绑定。映射缺失或冲突、要求刷新、正文版本缺失或任一匹配条件变化时，对受影响分片执行普通读取或提取。 |
| MEM-10 | 当新任务在同会话内的读取意图、来源及访问范围、账号、相关工具契约和环境均与已验证路线相符时，系统应先向一个适用分片给出建议。首个分片取得本轮可信正文后，系统才应向本批其他适用分片推荐这条路线。 | 已确认适用的同域新文档可先试用。无关目录条目变更后仍可匹配。每篇新文档按本轮审批和正文回执结算。 |
| MEM-11 | 如果只召回候选，或相关匹配条件改变、无法核实，系统应走普通路径。如果采用后只有超时、限流或回执缺失，系统应暂停该批推广，由原重试和备选路径处理。 | 同域公开文档和访问条件未知的新文档照常执行。切换账号、成员权限或相关工具，以及注入暂时异常后，原范围的历史路线仍可供后续适用任务核验。 |
| MEM-12 | 当已采用的路线收到可核对的同范围反证时，系统应立即停止向受影响分片推广，并持久化对应范围、路线版本及反证引用，即使任务随后停止。 | 单篇文档访问变化只影响该文档。可信的工具或认证范围失效停用对应范围。普通调度可继续，旧尝试或旧版本的迟到结果无法改写新版本。 |
| MEM-13 | 当普通路径在对应范围内取得晚于反证的可信成功证据时，系统应登记新版本并供后续任务重新验证。 | 通过原权限完成独立复验后恢复建议。单篇成功只恢复其已证实的适用范围。 |
| MEM-14 | 当在同一资料快照及等价账号、工具和初始历史上做匹配对照时，系统应提供覆盖、来源、审批、匹配决策和执行记录。 | 可核对从候选到建议、采用和正文验证通过的各步，记录误推荐、漏推荐、额外审批、重复探测及成本。关闭时按普通路径执行。 |
| MEM-15 | 当可信失败观察的适用条件与当前读取调用相符时，系统应提示避开已知失败的探测。 | 已确认适用的匿名入口或沙箱调用可在首次调用前收到提示。同域登录观察缺少当前适用证据时，普通网页读取仍可执行。 |

核查。MEM-06–09 对应原讨论的「能沉淀」和固定版本结果，扩展 MEM-01 的入库条件并保留 MEM-04 的严格匹配。MEM-10–11 和 MEM-15 对应「能迁移」，沿用 MEM-02 的单分片试用，明确失败观察的提示条件，并将 BT_Y184 的目录变化细化为相关条目变化。MEM-12–13 对应「能回退和恢复」，补齐 MEM-03 的证据范围和恢复版本。MEM-14 对应「能量化收益」及 MEM-05。响应以回执、索引、队列和发布结果核对。语雀完整性信号和可用于比较的认证范围仍需取证，未知时走普通路径。

## 取证样本

语雀的入库取证应覆盖脱敏后的真实登录页、普通重定向、可信正文、不同书库的同名 slug、截断和未知完整性。沙箱的 `/bin/ps` 观察须关联已结算的受控操作及已知 CLI 调用。间接执行只在能核实两者关系时纳入。用普通多文档入口确认这些回执如何绑定来源，及发布后是否可核对入库结果和缺口。匹配对照可直接预置同一组可信历史回执，独立评审匹配规则。
