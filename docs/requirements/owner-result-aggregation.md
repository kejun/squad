# 主笔树形归并

| 编号 | EARS 需求 | 核查 |
| --- | --- | --- |
| OTA-01 | 当普通自动分片均已结算、原始材料明显大于组交接材料，且至少两个组可以在已有成员和额度内并行时，系统应使用现有队列派发一层聚合工作。 | 宿主按实际载荷、可用委派和主笔输入预算选择组数。首期启发式使用现有读取页长做容量单位。小输入、额度不足或不可安全查读的材料沿原交接路径。 |
| OTA-02 | 当某组获准归并时，系统应从该组的已保存原始答复和产物提供有界材料，并保存带可信来源绑定的组产物。 | 正文格式随任务。覆盖、证据引用、冲突、缺口供主笔核对。超出直接输入预算的正文由已有 `readArtifact` 查读。组内只读提供的材料，不发起新采集或命令。 |
| OTA-03 | 当组工作结算时，系统应通过原交接仅安排一次当前主笔。主笔应取得用户要求、原分片来源索引、可用组产物和未解决缺口。 | 保留原始答复、产物和分片身份供回查。主笔输入避免同一正文从原讨论、消息和全量产物再次进入。主笔负责跨组融合与交付，独立检查继续核验原始来源。 |
| OTA-04 | 如果组工作失败、超时或被跳过，系统应保存原因和原始来源，并交给主笔处理缺口。重启、停止、目标变更和重复结果应使用现有的身份与额度守卫。 | 可用的部分答案可继续使用。失败组不冒充已完成内容，也不自动重跑源分片。 |

方案适用于普通自动分片后的调研、方案评审和工程交付。组负责整理同组材料，主笔按需回查原始结果并负责跨组计算、排序或对账。原执行凭证通过宿主保存的 ID 在主笔阶段按需读取。复用已有 `assistance` 工作、分片队列、`saveReports`、`readArtifact` 与 `DISCUSSION_HANDOFF`。首期只增加一层并行归并。

## 验证和模型对应关系

- `BT_Q58` 至 `BT_Q61` 覆盖三类分片、轻量和容量回退、重启后的结果去重，以及停止和目标版本隔离。对应流程见 [状态图](../state-diagrams.md)。
- 执行 `MODEL_BASE_URL=https://model.example/v1 MODEL_NAME=fixture node --import tsx tests/owner-result-aggregation-model-fixture.ts`。夹具驱动真实 XState 队列、交接、守卫和快照恢复。旧的形式化切片继续验证其有限域内已有的领取、额度、恢复及交接性质。新增的组计划、材料容量、只读和引用归属由本模型夹具及对应验收场景验证。
- SQLite、执行器和适配器场景使用受控模型响应，验证模型请求中的材料边界和实际的产物分页、执行凭证回读与主笔交接。真实模型的输出质量、总 token 和端到端 p95 需使用相同任务与模型进行对照。
