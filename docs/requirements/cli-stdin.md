# 工作区文件作为命令标准输入

用户原文要求把“OCR 用 stdin”固化为可执行工具知识。核实当前 `runCli` 没有输入通道，`runProcess` 总将 stdin 设为 ignore，只有知识文字不能完成动作。以下为实现该原要求所需的输入契约，不宣称云端 tesseract 就是用户原来使用的 OCR。

| 编号 | EARS 要求 | 验收与核查 |
| --- | --- | --- |
| R-SI01 | 当成员选用支持标准输入的命令且输入文件已在工作区时，系统应接受 `stdin:{path}` 并把文件原始字节送到 stdin，文件路径相对工作区根。 | Y145：真实二进制输入、EOF、OCR；保持结构化 argv。 |
| R-SI02 | 如果输入路径为绝对路径、父目录穿越、工作区外符号链接、私有配置或非普通文件，则系统应在启动前拒绝，并不读取外部内容。 | Y146；与现有工作区隔离一致。 |
| R-SI03 | 当宿主命令有 stdin 时，系统应在精确审批计划中显示输入路径、字节数和 SHA-256，并把这些信息纳入批准身份；如果批准后输入改变或被替换成越界链接，则系统应在启动前拒绝旧调用。 | Y147；不增加任何隐式授权。 |
| R-SI04 | 当 stdin 命令停止或超时时，系统应按现有命令生命周期终止、收口输入资源并保留明确回执；没有 stdin 的命令应继续得到关闭的输入。 | Y148；复用 existing queued/claimed/awaitingApproval/running/settled 状态，不引入新 actor。 |
| R-SI05 | 当 stdin 调用取得真实执行回执时，系统应持久保存经过脱敏的实际可执行文件、参数、目录、执行环境和已测 stdin 路径/大小/哈希；当候选进入固定检查时，系统应把这些宿主事实和校验输入是否变化的事实交给检查者，不使用候选自报替代。 | Y151；仅运行器的 LOCAL_RESULT 建立事实，owner DELIVER 的文字不建事实。 |
| R-SI06 | 如果固定证据中的调用、输入身份或校验事实被替换、删除，或旧冻结引用没有调用身份，则系统应拒绝该固定检查并返回 CHECK_EVIDENCE_CHANGED，要求重新提交候选以冻结新证据；旧回执没有已测输入时不得补造指纹。 | Y153；内部冻结原操作和脱敏执行回执，原始私有操作不得投影到模型。 |
| R-SI07 | 当 stdin 调用已两次可诊断失败时，系统应在重新测量当前字节后比较完整调用与输入身份；如果当前字节和调用环境仍相同，则系统应在第三次启动前拒绝，如果字节已经修正，则应允许新输入执行。 | Y152；请求层未知字节不得按路径代替内容。保留非 stdin 的既有重复失败守卫。 |
| R-SI08 | 如果成员尝试给未包含 stdin 的固定验证命令附加标准输入，则系统应在保存或领取操作前拒绝，不得扩大直接用户已冻结的验证输入范围。 | Y151/Y128；复用真实模型的固定检查权限边界。 |

核查结论：上述要求覆盖输入执行、边界、审批、取消/EOF；输入快照在批准核验后按实际哈希执行，不把路径文字当作输入内容。二进制不进入模型上下文或审批正文。所有 I/O 继续由已经持久化并成功领取的操作发起。

模型门槛：先在真实 `taskMachine` 的 `LocalModel` 上验证 stdin action 持久化、审批前不可启动、批准后可启动，以及停止/旧版本继续拒绝；再接入文件与进程 I/O。对应状态图见 `docs/state-diagrams.md` 的“标准输入与精确审批”。

实测补充：最初真实模型已通过沙盒 stdin 获得 HELLO，但固定检查只见 stdout 和 requestHash，没有实际调用及输入身份；因此保留原 partial 证据并先补可信证据链，不能用提高 token 预算替代。新事实沿用 LOCAL_RESULT → DELIVER 冻结 → CHECK_RESULT 重核的真实模型，重复输入在 I/O 准备时测量后再判断，不新增状态或隐式执行。

校验事实边界：`validationInputsChanged` 只有固定检查实际比较前后 source revision 时才是布尔值，普通 owner 调用未执行该比较时为 null。stdin 指纹证明实际读入的字节，不证明原文件在调用后没有变化；`.tmp` 不在普通工作区清单中，不能用 workspace revision 推断 `.tmp` 图片未改变。
