# XState 6 迁移

迁移基线为 `4cd5843`，生产状态机使用官方 npm 包 `xstate@6.0.0-beta.5`。该版本为预发布版本。以下要求以既有用户契约和真实持久化样本为依据。

| 编号 | 要求 | 验证 |
| --- | --- | --- |
| X6-01 | 当 Squad 处理现有任务、执行许可、房间、服务或监督事件时，应按已约定的状态、守卫顺序和结算规则运行。 | 比较 v5 基线与 v6 事件轨迹，执行现有模型与 Gherkin 门槛。 |
| X6-02 | 当 Squad 读取既有数据库或调试快照时，应恢复任务、当前尝试和历史终态。旧快照没有子 actor 时，该尝试须按既有恢复规则重新领取执行许可。已保存的子 actor 条目若缺少内嵌快照，或其身份或状态无效，应拒绝恢复。 | 回放由 v5.33.3 产生的各执行阶段快照，验证 SQLite 重开、一次性许可与坏数据拒绝。 |
| X6-03 | 当用户打开状态调试或 Inspector 时，应按原规则标识显示实际求值顺序，并通过现有弹窗握手发送状态。 | 复验微步证据、握手、父子 actor 投影及关闭清理。 |
| X6-04 | 当使用锁文件安装时，项目应解析到精确的 v6 Beta。旧版 Inspector 传输依赖在其工作区包内单独解析。 | 用常规 `npm ci` 核对版本树，检查浏览器构建和观察测试。 |

任务转移从同一份有序规则表生成 v6 处理函数和调试规则。快照编解码在任务持久化边界处理旧数据，执行器按已提交的许可启动。Inspector 的兼容包只负责现有传输，使用来自 v6 模型的观察数据。
