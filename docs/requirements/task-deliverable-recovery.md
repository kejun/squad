# 本地文件交付与续办

这次群聊任务要求把用户指定的本地 Markdown 分享稿转成可在 Chrome 打开的 HTML。用户的执行轨迹记录了输入协议修复、宿主审批过期、跳过旧审批干扰后续请求、文件生成后交付失败，以及显式续办沿用旧截止时间。目标是在既有审批、任务执行和群聊交付机制内修正这些行为。

| 编号 | EARS 需求 | 对应验收 |
| --- | --- | --- |
| HTML01 | 当当前负责人声明交付工作区内的文件，且获准命令成功生成该路径的有效文本文件时，系统应在结算命令的事务中保存文件原文。 | BT_A67–A69 |
| HTML02 | 当负责人提交交付结论时，系统应在候选中复用已保存文件。如果负责人工作失败，系统应在群聊失败消息中提供已保存文件的下载入口。 | BT_A67–A68 |
| HTML03 | 如果输入解释或工具请求违反协议，则系统应在现有修复额度内给出由协议定义的出错字段，并记录字段和问题码。达到修复边界时应结算，且不得执行无效动作或记录未经验证的字段和值。 | BT_I30、BT_M73 |
| HTML04 | 当用户明确继续或从失败沙箱记录发起有效宿主续办，且任务硬窗口仍有效时，系统应在原硬期限与已有额度内按新工作时限启动。如果硬窗口已到期，系统应要求明确授权新窗口，授权后允许重试原来未获受理的请求。 | BT_Y203、BT_Y205 |
| HTML05 | 当同一工作已处理已结算命令的回执并发起后续工具操作或模型请求时，系统应关闭原命令的审批入口，拒绝旧入口上的迟到决定并保留后续执行。 | BT_Y204 |

HTML01–02 对应文件已落盘而群聊缺少附件的问题。登记范围为负责人声明的新建或改变的工作区普通 UTF‑8 文件，每次命令可登记一个不超过 1 MiB 的文件。文件接入现有工具授权、持久回执、交付检查及下载机制。用户需要的桌面副本沿用宿主审批。停止或目标改变后的迟到回执只结算操作。失败消息提供下载时应保留任务的失败或待核验状态。

HTML03 对应原轨迹中的两次协议错误及诊断缺口。字段可在受控模型请求和执行记录中查验。使用现有格式修复事件和观测记录，权限、重试额度和原始约束仍由既有守卫执行。原运行的无效字段缺少记录，无法从本次回归输入反推。

HTML04 对应 11:36–11:37 的续办。用户明确续办时结束自动修复阶段，保留任务总期限、已用额度和原审批期限。任务总期限到期时使用已有的「授权新窗口并继续」入口。HTML05 对应跳过旧审批中断后续执行。若命令到期后工作仍未转入新操作，原权限决定依旧等待用户。两个条目各由真实任务模型验证可观察的领取结果与操作状态。
