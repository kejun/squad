# 分层摘要

需求来自当前任务产物篇数不受载荷上限约束。固定检查材料仍是全文。`@BT_Q07`、`@BT_Q09`、`@BT_Q11` 仍是一次归并或整份回退，不改写成这条路径。

## EARS 与核查

| 编号 | 要求 | 核查 |
| --- | --- | --- |
| HS-01 | 当汇总语料是当前任务产物且其正文不能放进一条 4000 码点的短产物时，系统应按该页能容纳的直接来源数分批，并用现有 `mapReduceCapacity` 与队列派发。每批请求只带本批产物编号。 | 与设计一致。触发是用户要求汇总或归纳，且当前目标版本产物的正文码点超过 `readSavedArtifact` 的一页。八份历史文档没有当前任务产物，不进入这条路径。扇入由页长和来源编号骨架决定，不是新的固定片数。 |
| HS-02 | 当一批结算且草稿含直接来源编号与要点、正文不超过 4000 个 Unicode 码点时，系统应把它保存为一条普通产物，并由宿主分配产物编号。 | 保存仍走 `saveReports`。编号形如 `${taskId}:artifact:${eventId}:${index}`。超页草稿不保存。 |
| HS-03 | 当已保存的短产物多于一条时，系统应把这些短产物的编号作为下一层来源再归并。层数随文章数增加。全部层完成时只剩一条不超过同一预算的顶层摘要。 | 复用 `advanceMapQueue`、`recordMapResult`、`summarizeDiscussion`。一层里批次数超过容量时顺序再开一轮，并重新计算容量。不新增父状态或摘要库。 |
| HS-04 | 当顶层摘要已在预算内且系统组装方案师请求时，系统应只放入该摘要正文及其直接来源索引。读取其中一篇应通过现有 `readArtifact` 完成。同一次请求不包含整层正文。 | 索引含产物编号、`documentId`、`revision`、`goalVersion`，不含 `content`。 |
| HS-05 | 如果顶层那一条摘要的正文超过 4000 个 Unicode 码点，则系统应终止汇总路径且不发出携带文章正文的方案师请求。 | 不截断、不升格超页草稿、不把文章回填进方案师请求。 |
| HS-06 | 当文章数为 100、1000 或更多而顶层摘要仍在预算内时，系统应完成到方案师请求。方案师请求的汇总材料体积不随文章数增长。 | 汇总材料只计顶层正文和直接来源索引。 |
| HS-07 | 如果固定检查材料超过检查请求所能容纳的全文，则系统应按现有检查路径失败，并保持材料全文。该结果不由汇总路径改写。 | 不改 `fixedCheckMaterials`、`CHECK_CONTEXT_LIMIT` 或 `enforceFixedContext` 的启用条件。 |
| HS-08 | 当协助额度、普通额度或可用成员不足以再派发一轮时，系统应保留现有容量失败，并且不把未归并的文章正文写入方案师请求。 | 原因仍是可用成员不足、协助额度不足或普通额度不足。未形成顶层时不发方案师汇总请求。 |

理解、分片和归并请求在这条路径上不内联文章正文、短产物正文或 `discussion.results[].answer`。目标、约束、已解析的 `inputIntents` 和名册仍在载荷里。提供方截断不作为装下这些文章的手段。
