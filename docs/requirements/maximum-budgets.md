# 最大执行预算与无损工具元数据

用户输入：放开限制，所有预算尽可能大；以顺利完成任务为目标，必要时撤掉应用配额；模型contextWindow默认按deepseek-v4.1-flash最大设置。现场证据：2476条CLI中1806条用途未知；约105万输入token；同一分片先多次200，后400 invalid_request_error，另有MODEL_OUTPUT_LIMIT。

核查：三小时是此前要求，本轮“所有预算尽可能大”将新默认工作/处理窗口改为2,147,483,647ms（约24.85天）；历史已保存窗口不暗改。调用计数取Number.MAX_SAFE_INTEGER，属于实际可表示的最大配额，不宣称数学无限。调度轮询、审批、权限、结算及协议有效性不是消耗预算，不随之撤除。

真实上限来源：2026-11-12读取 https://opencode.ai/inference/openai/v1/models ，deepseek-v4.1-flash的limit.context=1000000（取整）、limit.output=384000；同日实际上游400报告prompt上限1048571，默认context采用实测值。应用不能把该服务的物理容量变大；输出预算和输入共享上下文，默认最大输出不是每次必须生成的长度。旧环境显式设置的MAX_TOKENS仍需按实际期望配置。

状态范围：配额仍由真实taskMachine原消费/停止/领取守卫拥有；元数据共享是模型输入投影，不新增状态。先用真实模型检查高额度可领取及消费、不产生工具授权，再接入配置和序列化。只运行这些受影响场景和原协议/配置回归，不重复未变的OCR、浏览器和TLA探索。

MAX-07：当新默认任务使用最大修订/重试配额时，交付周期不得再被隐藏的2–3次修订或单次网络重试上限提前结束。原有限配置和旧周期保留原界限；停止、未知效果与固定证据要求不变。Y161覆盖四次修订及三次技术重试，先通过真实模型轨迹再纳入最终接线。
