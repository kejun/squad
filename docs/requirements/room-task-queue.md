# 同群独立委托

用户要求在同一工作群接收独立的新委托。可观察的结果是新委托有独立归属、可以排队并能在轮到时自动开始，原任务继续接收自己的补充和回复。

| 编号 | EARS 需求 | 验收场景 |
| --- | --- | --- |
| ROOM-QUEUE-01 | 当用户明确在已有主任务的群内提交独立委托时，系统应原子保存新任务、负责人和排队回执，保持当前主任务的目标、消息归属和执行不变。 | BT_R06 |
| ROOM-QUEUE-02 | 当同群多条新委托同时提交时，系统应分别保存每条委托，只开始第一条，其余按接收顺序等待。同一请求再次提交时应返回原任务标识。 | BT_R13 |
| ROOM-QUEUE-03 | 当活动主任务结算且有等待中的委托时，系统应开始最早的等待任务，从这时计算执行窗口。重启应保留已登记委托的顺序和来源。 | BT_R14 |
| ROOM-QUEUE-04 | 当用户明确停止一条尚在队列中的委托时，系统应将它标记为已停止，不派发其工作，也不停止当前任务。 | BT_R15 |
| ROOM-QUEUE-05 | 当群已有任务时，用户应能在同一个输入框明确提交独立委托；普通补充和等待中的答复仍应关联当前任务。 | BT_R16 |

上述规则沿用主任务单工作位和现有目标保护。排队期间没有可领取的执行意图，不消耗任务执行时长。带任务标识的回复不能借用另一任务的归属，来源校验和命令去重仍在接收事务中。任务执行器继续使用已有工作领取和资源校验。

[同群委托状态图](../state-diagrams.md#同群独立委托)列出开始和停止的边界。真实 XState 仿真从排队快照恢复，到期监督不会创建工作，取得工作位后才开始计时。可运行 `npm run simulate:discussion`。路由场景覆盖排队、回执去重、取消、恢复以及网页补充的任务归属。
