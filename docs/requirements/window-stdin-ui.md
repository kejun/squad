# 窗口续期与标准输入的可见决定

此文记录 WIN-01–WIN-04 与结构化标准输入的网页验收，不增加业务状态。

| 编号 | EARS 要求 | 核查与验收 |
| --- | --- | --- |
| WUI-01 | 当任务窗口到期并已保存续窗人类门时，网页应自动展示 `WINDOW_EXPIRED` 及明确续窗操作；当用户关闭提示或重新载入时，系统应保留原门和原期限。 | 对应用户的显式失败、优先 newWindow 要求，BT_Y149；关闭不是结束或授权。 |
| WUI-02 | 当用户通过网页明确授权新窗口时，网页应默认提供 180 分钟并将明确决定保存到当前门，系统应更新窗口且保留成果及已用额度。 | 对应三小时预算，BT_Y149；显式时长可修改，不重写旧窗口。 |
| WUI-04 | 在原窗口已到期并等待明确续窗决定时，如果原排队操作依赖的旧效果仍持有冲突租约，则当前会话应继续展示该旧操作的精确核对入口；当真实租约已结算或目标版本已变更时，不应把旧来源投影为当前阻塞。 | 对应原资源核对与本次非静默续窗要求，BT_Y118；只读真实租约，不恢复取消的操作或授予执行。 |
| WUI-03 | 当宿主调用带有工作区文件标准输入并等待授权时，网页应展示完整命令、目录、输入相对路径、字节数与内容指纹；在用户明确批准前不得启动进程。 | 对应可执行 OCR stdin 配方及原精确授权约束，BT_Y150；展示元数据不展示私有文件正文，不取得额外权限。 |

核查结论：条件与可观察结果明确；既有 host approval 与 waitingHuman 状态能完整表达两类决定。网页只投影保存的失败、门与精确计划，不新建业务状态，不在浏览器中推测执行效果。先复验真实 taskMachine 的窗口到期/续窗及 stdin 审批模型门槛，再接投影。验收使用实际 Chromium → HTTP → WebService/Engine → SQLite，外部模型由可控适配器替换，不伪造业务 API。
