# 交付后的执行摘要

用户确认「只保留执行摘要」。群聊中的新交付由宿主根据已保存的结果汇报执行情况。

| 编号 | EARS 需求 | 核查 |
| --- | --- | --- |
| ESR-01 | 当主笔提交当前有效的交付且宿主允许结算时，系统应发布原交付并发送一条简短执行摘要。 | 使用已保存的本轮正文、文件与分片结果。无需逐项判据、模型请求或工具操作。 |
| ESR-02 | 如果仍有失败、部分完成或缺少必要材料，系统应在摘要说明已知缺口。 | 已保存的部分成果继续交付。任务身份、用户决定、必需资源凭证和外部效果守卫继续生效。 |
| ESR-03 | 当用户提交旧「重试检查」命令时，摘要模式的宿主应说明当前采用执行摘要并保持交付可访问。 | 不创建新的核检工作。已发布的历史检查结果仍可查阅。 |
| ESR-04 | 当兼容宿主恢复已有核检工作时，系统应依原快照处理已绑定的工作及结果。 | 已创建的旧工作通过既有版本和权限守卫结算。群聊新任务采用摘要模式。 |

验收 BT_F88–BT_F90。BT_F85–F87 继续验证历史核检协议。状态图见[交付完成与执行摘要](../state-diagrams.md#交付完成与执行摘要)。
