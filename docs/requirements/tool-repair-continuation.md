# 分片工具请求的续办

用户报告「第 8 篇文档提取」在一次工具参数局部修正失败后零产物，汇总显示 INVALID_TOOL_REQUEST。提供的记录指向 builder-1 的第四次模型请求。现有本地数据库没有本次任务，原工具与原始参数待核实。

| 编号 | EARS 需求 | 核查 |
| --- | --- | --- |
| TRC-01 | 当独立分片的工具参数局部修正仍无效或报告无法修正时，如果当前工作仍有效且有普通请求额度，系统应在同一分片内用已经取得的材料请求一次最终答复。 | 复用现有领取、预算、停止和结果身份校验。被拒动作与已结算动作均不重放。 |
| TRC-02 | 当分片用已有材料给出有效的部分结果时，系统应保存正文、产物和真实状态并交回主笔。 | 继续使用 DISCUSSION_RESULT 与现有分片队列。 |
| TRC-03 | 如果分片已无可用结果、最终答复无效或续办额度不足，系统应按现有失败流程交接缺口。 | 续办只允许最终答复。继续拒绝工具动作及无效协议，无第二次完成请求。 |

验收见 BT_M70–M72。涉及当前工作内的适配器处理流程，无新任务状态或额外自动工作。

## 验证

BT_M70 的三个受控修正结果在原适配器均触发「修正后的工具请求仍不符合协议」，只完成三次模型请求，分片无产物。修复后局部修正仍只收到两条紧凑消息。同一个分片请求一次最终答复，已有资料及部分结果正常交接。BT_M71、M72 复验最终答复的工具拒绝及归并预留额度。运行 `node --import tsx tests/tool-action-repair-model-fixture.ts` 复验真实 XState 的领取、局部修正计费、取消和部分结果结算。
