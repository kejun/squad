# 回执投影

原始要求来自回执投影方案：模型请求里，除刚刚返回的那一条工具结果外，已落库的更早结果改成从回执派生的索引卡。不另建模型可写的结果文件库、记忆目录或摘要。当前交付产物和固定检查材料保持全文。

## EARS 与核查

| 编号 | 要求 | 直接验收 |
| --- | --- | --- |
| RP-01 | 当系统为同一次已授权工作组装模型请求时，系统应保留最近一条工具结果的有界原文，并把更早且已经落库的命令回执、技能资源页和网页抓取页改写成不含正文的索引卡；助手发出的工具调用记录应保留。 | BT_M60 |
| RP-02 | 系统应在组请求时从已结算回执当场派生索引卡。卡片应包含操作号或证据号、成败、代码、退出码、截断或完整性、内容哈希、字符数与字节数、已读偏移、后续游标和保存边界；网页抓取卡还应包含证据引用、偏移和总长度，并标明正文不在该消息中。 | BT_M60、BT_M62 |
| RP-03 | 当保存本地检查点时，系统应把已经成功落库的目录发现和技能目录回执保存为操作号，而不是目录正文。 | BT_M61 |
| RP-04 | 如果网页搜索或技能搜索还没有持久回执，则系统应在模型请求中保持其有界原文。 | BT_M62 |
| RP-05 | 如果检查点里的旧正文与已结算回执不一致，则系统应按回执的内容哈希生成索引卡，不得把检查点里的旧正文当作该卡的正文。 | BT_M63 |
| RP-06 | 在组装检查请求时，系统应保持当前候选全文和已绑定证据正文完整出现；固定输入装不下时仍应失败，不得静默截断。 | BT_M64 |
| RP-07 | 如果较早的已落库回执失败或正文缺失，则索引卡应使用该回执的原代码，且不得补写正文。 | BT_M65 |
| RP-08 | 系统不得为投影新增模型可写存储或任务顶层状态。已保存证据的首次分页读取仍消耗一次普通额度，同一读取在确认未开始后重新领取不另扣。 | 状态模型复验 |

核查：八条保留方案中的投影范围、索引字段、目录检查点、搜索原文、回执优先、固定全文、失败代码和原额度。刚刚返回的目录结果仍可在紧接着的那一次内存请求中保留有界原文；检查点从结算时起只保存操作号，恢复后的请求不再重放目录正文。搜索结果在没有回执时不投影，也不假装已经保存。当前产物和固定来源不参与替换。没有新增父状态、并行区域或执行队列。

## 模型先行边界

投影不新增生命周期。目录正文的保存形式是既有 `LOCAL_REQUEST` / `LOCAL_RESULT` 的上下文更新，所有者是 `src/local-operation.ts`。模型请求中的索引卡由 `src/model-adapter.ts` 在组 `requestMessages` 时派生，不改变领取、执行或回传。`readEvidence` 仍走 `LOCAL_REQUEST → LOCAL_CLAIM → LOCAL_RESULT`。先运行 `tests/receipt-projection-model-fixture.ts`，再接入请求组装。
