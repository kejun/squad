# 交付完成与核检结果

| 编号 | EARS 需求 | 核查 |
| --- | --- | --- |
| ADC-01 | 当当前候选可交付且最终检查得到结论、未获得检查额度或耗尽补试时，系统应发布当前候选并将任务记为完成。 | 检查仍逐项判定。用户停止、候选版本无效、必需资源凭证失效、未决外部效果和任务级处理窗口继续使用现有守卫。 |
| ADC-02 | 当检查有发现或未完成时，核检员应发送包含具体问题与重试询问的独立消息。 | 协议失败记录宿主已知的错误类型和漏项编号。被拒的模型原文无需保存。已完成的检查结果保留失败或未核实判定。 |
| ADC-03 | 当用户明确回复「重试检查」且当前交付仍有效并有检查额度时，系统应对同一份交付安排一次检查。 | 复用固定材料和检查执行路径。已有交付可继续查看，旧结果与重复命令不得覆盖当前交付或重复收费。 |

用户反馈涉及错误顶层类型与漏判据后被记为部分完成。对应规格为 BT_F85–BT_F87，状态图见[交付完成与核检结果](../state-diagrams.md#交付完成与核检结果)。
