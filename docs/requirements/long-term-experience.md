# 长期执行经验

用户要求落地交付后可复用、能凭执行结果优化的会话记忆，并验证结果复用能减少重复执行。方案已确认按会话保存在 SQLite，群内继续使用执行摘要。

| 编号 | 需求 | 验收 |
|---|---|---|
| MEM-01 | 当任务成功发布且存在可信失败或完整正文回执，系统应独立记录对应经验。后台处理失败时，交付仍成立，恢复后可补记且不得重复计数。 | BT_Y181、BT_Y188、BT_Y190–Y191 |
| MEM-02 | 当同会话新任务的访问范围、账号及相关工具匹配历史路线，系统应先为一个适用分片提供建议。收到当前可信的完整正文回执后，系统才可向同范围其他分片推荐。实际执行仍需本轮许可。 | BT_Y182、BT_Y192–Y193、BT_Y197 |
| MEM-03 | 当推荐被实际采用，系统应按可信结果更新对应经验版本。可信反证使受影响范围恢复普通调度，任务终止后仍保留对应版本和反证引用。适用条件变化或暂时异常时，系统按普通路径执行。可信复验可恢复对应范围。 | BT_Y183–Y184、BT_Y189、BT_Y194–Y195、BT_Y199–Y201 |
| MEM-04 | 当当前请求声明来源版本，且同会话存在身份、正文版本和提取要求均匹配的成功分片，系统应沿用其原产物与来源身份并跳过重复派发。刷新要求、未知版本和条件变化的分片继续正常执行。 | BT_Y185–Y186 |
| MEM-05 | 当关闭长期经验，系统应按原流程执行。对相同输入做开关对照时，可核对分片覆盖、来源、实际工具及模型请求。 | BT_Y187 |

核查结论。发布已经持久化，目录和读取凭证已有可信入口，分片已有队列及交接。新增范围是房间内的经验记录、单分片验证、反馈，以及按明确版本匹配的结果索引。网页链接一般不提供可核对的当前版本，首期支持调用方明确声明已保存正文的 SHA-256。普通链接或要求重新读取时需要本轮获取。命中经验不会授予权限，模型不会与用户新增交付互动。

## 使用与复验

网页服务默认启用。启动前设置 `SQUAD_EXECUTION_MEMORY=off` 可关闭经验采集和应用。

普通文档链接在已确认访问范围及环境相符时可命中读取路线。账号或范围不明时按普通路径读取。 [读取契约配置](../local-tools.md#长期读取经验)需要复用旧产物时，在请求中把来源 URL 与已核对正文的 SHA-256 写在同一行，格式为 `<URL> sha256:<64位十六进制>`。一行对应一个来源，提取说明另写。只有匹配已发布结果、来源身份与同一提取说明时才复用。SHA-256 对应宿主回执的 `contentHash`。请求最新或重新读取时，仍要求本轮凭证。

```sh
MODEL_BASE_URL=http://127.0.0.1:1/v1 MODEL_NAME=fixture TSX_TSCONFIG_PATH=tests/bdd/tsconfig.json \
  node --import tsx node_modules/@cucumber/cucumber/bin/cucumber.js \
  features/80_long_term_experience.feature --import 'tests/bdd/*.ts' --format progress
```

模型层使用真实 XState 和受控事件。集成场景使用临时 SQLite、真实供应商协议适配器与 Runner，供应商响应和网页正文受控，文档读取器在本地夹具进程运行。BT_Y187 对比最终内容、八篇来源、分片派发和模型 HTTP 请求数。BT_Y192 核对同源新文档、按次宿主授权和候选到正文验证的统计。使用 `scripts/execution-measurement.ts` 可读取任务的分片决策、入库缺口和原有工具及模型耗时。 [模式匹配与失效处理](long-term-experience-patterns.md)
