# 围绕最终交付的 Agent 交接

用户要求多 Agent 围绕同一最终目标分工，并在分派子任务、归并和检查最终交付时沿用这套目标关系。

| 编号 | EARS 需求 | 验收 |
|---|---|---|
| GA-01 | 当模型解释用户请求并规划可并行工作时，系统应要求每个分片说明它支持的最终要求、负责范围和可核对的产物，并用归并要求说明产物如何合成最终交付。 | BT_S14 `interpretation` |
| GA-02 | 当负责人或协调员分派协助时，系统应要求分派方明确当前缺口、子目标范围和完成条件。当子 Agent 领取工作时，系统应要求它按已分派子目标交付可合并的结果、依据和剩余缺口。 | BT_S14 `owner`、`facilitator`、`assistance` |
| GA-03 | 当普通归并或负责人整合结果时，系统应要求按最终验收组织结果，统一可比较的口径、处理重复和冲突并保留覆盖缺口。分层摘要应在原页长内优先保留对最终结论有影响的材料及来源。 | BT_S14 `discussionSummary`、`owner`，BT_Q57 |
| GA-04 | 当下游检查收到组装后的候选时，系统应要求它依据用户原文与当前验收逐项检查整份交付。如果关键缺口可以在已有授权内补齐，则检查员应在同一工作中补证并修正。材料足够时直接判断。 | BT_S14 `check`、BT_S05、BT_E128–E129 |
| GA-05 | 当宿主调用输入理解模型时，系统应在同一次请求中要求模型结合独立只读工作的体量、当前可用并发、重复输入和归并开销决定是否分工。单一轻量产物、简短核对和强依赖任务可由负责人直接处理。 | BT_Q62 |
| GA-06 | 当可独立执行的轻量资料适用同一核对规则且合并能减少交接开销时，系统应允许模型按明确的共同检查口径合组，并要求每份来源有独立可追溯的结果。工作量大的独立来源仍可分别排队。 | BT_Q62、BT_Q34–Q35、BT_Q27 |

现有的 `objective`、`expectedOutput`、`synthesis`、`question`、`expected` 及 `reason` 足以表达这些要求。子目标描述对当前用户要求的贡献。采用现有模型请求模板和原输出协议。引用、依赖、失败范围和判断依据留在当前职责允许的字段。领取、调度、权限、期限和必需凭证的校验由原状态机及宿主负责。

验收观察真实适配器发出的角色指令及其实际工作身份。受控模型提供确定的回传，生产模型在实际任务中的内容表现属于独立验证范围。

首期依据用户确认的三步识别流程，只细化理解模型的分工判断。GA-05–GA-06 的输入、响应和验收均可通过现有理解意图、模型请求及分片计划观察。分片范围、产物和归并要求沿用原协议，宿主依既有额度与权限决定派发。合并是降低协调成本的建议，适用于有共同检查口径且完整保留来源的工作。

## CI 进程回执回归

CI 的 BT_L121、BT_Y123 和 BT_Y71 曾在短命令结束时报告效果未知。目录刷新在合并前基线复现，出错执行读取 `/proc/<pid>/stat` 时收到 `ESRCH`。采样现在将该返回按已有的进程已退出处理，真实退出事件仍决定结果。

`tests/local-tools-durability.test.ts` 在真实子进程退出时注入这一操作系统返回，覆盖退出码 0 和 1。旧代码两例均误报 `CLI_NOT_FOUND` 和未知效果，修复后保存各自的退出回执。这个时序验证补充 BT_L121、BT_Y123 和 BT_Y71 的产品验收，三个场景大纲及新增提示词验收共 15 例通过。盲目重放和虚构回执的故障注入仍被检出。
