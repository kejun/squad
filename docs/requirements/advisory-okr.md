# 轻量 OKR

用户确认 OKR 提供指导、简单关联和手动状态标记。任务可选一个主要 KR，原交付流程负责任务完成。

| 编号 | EARS 需求 | 场景 |
|---|---|---|
| OKR-01 | 当用户在群聊记录目标和关键结果时，系统应保存所属群聊、目标与 KR 的关系，并允许把 KR 手动标记为待推进、进行中或已达成。重启后应保留记录。 | BT_O13 |
| OKR-02 | 当用户创建任务并选择当前群的一个 KR 时，系统应保存关联，并为 Agent 提供该目标及 KR 的文字作为参考。任务补充和恢复应保留关联。 | BT_O14 |
| OKR-03 | 当任务有可发布的结果时，系统应按现有交付规则完成任务。KR 状态由用户手动维护。未选 KR 的任务也可提交。 | BT_O14–BT_O15 |
| OKR-04 | 如果提交的 KR 不属于当前群聊，系统应拒绝该关联。删除群聊时应一并移除其 OKR 记录。 | BT_O16–BT_O17 |

已核对张力点。KR 只表达方向，参与 Agent 的参考语境。原始用户输入继续决定任务目标、验收和工具权限。建任务时由宿主从当前群的记录解析 KR，任务保存稳定身份和当时的文字，状态仍由群聊拥有。管理范围为新增目标、添加 KR 和改状态，复用群聊边界及任务详情。

## 源码对应审查

产品提交 `f77d0ff` 相对 `a394a9b` 增加了群聊和任务快照中的可选字段。旧快照按缺少 OKR 读取。覆盖 WebService 的验证入口同时纳入新导入的 `src/web/okr.ts`。

| 范围 | 对应关系 |
|---|---|
| 协调、交接 | 关联随可信提交在创建任务时保存。原 XState 状态及守卫负责生成、领取和恢复工作。调整目标保留已选 KR。 |
| 授权、本地效果、宿主续办 | API 按当前群聊解析 KR，模型把其文字当参考。工具许可、领取、预算、回执和结果处理沿用原有路径。 |
| 交付 | 交付检查由当前任务的直接要求生成固定判据。KR 的手动状态及用户操作通过独立群聊事务提交。 |
| 群聊存储和删除 | OKR 和变更回执写在现有群聊事务中。删除仍清理同一份群聊数据和回执，兼容无 OKR 的旧快照。 |

模型层复验关联与未关联任务的正常交付、相同的判据，以及目标版本变化后的关联保留。真实 HTTP 与受控模型的 Gherkin 验收覆盖重启、重复提交、关联、跨群隔离和删除。Chromium 桌面与移动视窗复验新增目标、添加与手动更新 KR，以及提交和查看关联任务。
