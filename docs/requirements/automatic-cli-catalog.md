# 自动 CLI 工具目录

原始要求：工具目录应自动生成并说明适用场景；不要求人工配置；取消单条 2000 字符、总量 200 条、每页 20 条、discoverHost.commands 每次 20 个的限制。

## EARS 与核查

| ID | 可观察要求 | 验收 |
| --- | --- | --- |
| R-C01 | 当服务没有显式 CLI 目录时，系统应根据宿主和沙盒有效 PATH 自动发现可执行命令，并向模型提供完整目录及按执行环境区分的已发现路径。 | BT_Y135 |
| R-C02 | 当本机安装包或手册包含属于当前实际可执行路径的用途说明时，系统应自动提供该说明、适用场景和资料来源；如果缺少所属说明，则应明确用途未知而不按命令名借用其他安装位置的同名说明。 | BT_Y135、BT_Y136 |
| R-C03 | 当生成或刷新目录时，系统应仅读取静态元数据，不运行命令、帮助或登录探测，不产生宿主执行授权。 | BT_Y135、BT_Y139 |
| R-C04 | 当目录超过原数量、条目或分页限制时，系统应完整接收、返回和交给模型，不以总字节限制替代这些已删除限制。 | BT_Y137、BT_Y138 |
| R-C05 | 当一次显式发现超过 20 个命令时，系统应接受全部有效裸命令名并逐一报告存在性，仍拒绝路径、空字符和伪造授权。 | BT_Y138、BT_L101 |
| R-C06 | 当后台观察到命令或说明变化时，系统应原子发布新的完整目录，模型请求读取已发布快照；如果刷新失败，则应保留最后有效版本并公开诊断。 | BT_Y139、BT_Y123 |
| R-C07 | 当宿主显式配置目录或空目录时，系统应保持兼容；显式配置只提供元数据，不能授予执行、认证或网络权限。 | BT_Y129、BT_L103 |
| R-C08 | 当自动目录存在性观察与已结算执行回执冲突时，系统应按观察时间采用较新的存在性事实；时间相同时实际执行回执优先，不能仅偏向已安装，也不能由存在性推断认证或网络已满足。 | BT_Y139 |
| R-C09 | 当实际调用比已登记示例额外携带标准输入时，系统应保持其原始回执，但不得把该调用的认证或拒绝状态泛化为没有标准输入的已登记调用状态。 | BT_Y126 |

核查结论：九项覆盖用户原始限制、自动化、可理解性和权限边界；静态说明不是实际执行成功证据。自动扫描已确认的存在性直接进入带目录版本和观察时间的 readiness，认证、网络和授权仍分别未知或要求批准。同名宿主与沙盒命令的不同路径及用途不能互相替代。自动扫描不凭工具名生成未经核实的认证、网络能力或具体参数。配置仍可用于兼容嵌入，但正常服务无需配置。命令数量和资料长度不设产品上限；并发扫描和缓存只控制执行效率，不隐藏工具。

## 数据与生命周期

目录条目延续 command/description/examples 等字段，新增 scenarios（适用场景）和 documentation（资料状态、来源及引用）。没有说明的命令仍保留，documentation.state 为 unknown。自动目录从有效 PATH 枚举，按优先级去重，读取相邻 npm 包描述、系统安装包说明或本机 man 内容；不运行子进程、不读账号凭据。显式目录兼容旧字段。

目录观察属于 ToolInventoryStore 的现有快照生命周期，不增加任务状态。任务执行继续复用真实 taskMachine 的 LOCAL_REQUEST → LOCAL_CLAIM → LOCAL_RESULT 与宿主批准路径。实现前复验 host-model-gate；模型的停止、权限、持久化和额度守卫继续拥有执行权。目录结果属于元数据，完整性不会被普通命令 stdout 上限截断；普通命令输出仍保留原限制。旧版本绑定的游标只用于兼容读取剩余内容，不再生成固定 20 条分页。

BT_Y136 还直接覆盖 PATH 前置 wrapper 与另一安装位置的同名手册：wrapper 保持 unknown；另一环境的二进制与手册由同一 dpkg 包明确拥有时，仍获得真实命令级 man 用途。独立复查复现了修复前错误及修复后的正负路径；不是通过禁用全部手册来掩盖问题。手册引用包含实际资料路径，真实路径不同的包装器不会借用别的全局同名说明。

R-C08 的 Y139 通过真实 taskMachine 保存失败回执与受控时钟验证两种次序：执行 NOT_FOUND（150）覆盖旧目录（100），新目录（200）再覆盖旧失败（150）；不取乐观值，不推断登录或联网。R-C09 的 Y126 通过两个真实 Node 进程验证同 argv 但不同 stdin 的调用：带额外 stdin 的认证错误不标记无 stdin 的目录示例，实际无 stdin 调用的认证错误仍被保留。两项均有先行模型门槛、业务红例和单表达式生产故障负控。
