## 逐项处置记录

每份分类 JSON 使用原用例的完整名称定位，记录原文件、处置、理由、承接的 `@BT_*` 或适用验证命令及证据。混合文件按实际验证边界分组；同类组列出全部原名称，不能用文件后缀代替审计。非 unit 入口中的独立单测也纳入迁移。

- `ui.json`：内容渲染、Inspector、调试投影、面板与归档。
- `host.json`：审批、会话、续办与宿主能力。
- `core.json`：本地操作、技能、协议、额度及协调。
- `delivery.json`：交付、证据、来源解析与产物展示。
- `map.json`：分片容量、汇总与执行计量。
- `other.json`：其余入口逐项分类及隐藏单元用例；委派迁移项引用前述记录。

原名称在 unit 清单中须恰有一项处置，在其他入口清单中也须恰有一项处置；委派项只在总计中计一次。新增准入单测或断言的评审字段遵循根目录 `AGENTS.md`，这里的历史记录不构成未来单测的自动准入。

## 承接与验证方法

迁移优先复用原场景、大纲和无测试框架依赖的夹具，补齐缺失的业务条件与具体结果。直接执行承接场景、确认原断言检出对应回归后，再删除重复 Vitest 包装。纯模型驱动可独立运行作为 XState 实现前门槛；真实 Engine、Store、Runner、DOM 和外部边界继续在原有完整检查中验证。

各模块记录自己的目标场景运行、故障检出和独立模型命令。最终完整检查与清理后覆盖汇总在本页补记；不以测试数量下降、相同标签或仅类型检查作为承接证据。
