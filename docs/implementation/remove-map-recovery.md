# 移除分片补救申报与子 Agent 内容验收

原始要求：彻底移除补救申报、补救验收和逐条核对申报分片；不必核对子 Agent 的交付，执行失败时交付为空。现场错误 `MAP_RECOVERY_PARTITION_NOT_UNRESOLVED`：负责人把 succeeded 分片列入补救声明，机械预检退回，负责人反复修订而无法交付。

## EARS 与核查

- MRM-01：当子 Agent 返回成功或部分成功时，系统应按其返回的状态、正文和产物交给汇总，不追加来源回执核对或改变其状态。
- MRM-02：如果子 Agent 执行失败、超时或明确报告失败，则系统应提供空正文和空产物列表，并接受子 Agent 直接返回空失败正文；失败状态与诊断应独立保留，不得当作交付正文。不会交付的失败文件直接丢弃，不为其格式触发重新申报。
- MRM-03：当负责人汇总子 Agent 结果并交付时，系统应只走原任务的普通交付流程，不要求补救声明、逐片来源匹配、补救验收项或证明登记，旧分片失败不得形成永久交付门槛。
- MRM-04：如果旧模型输出或保存的任务包含补救声明、证明或验收项，则系统应忽略这些已移除字段并清理活动上下文，恢复执行时不得再次产生补救申报错误或要求格式修正。
- MRM-05：当收到停止后的输出、旧目标或旧尝试的结果时，系统应继续拒绝过期结果；宿主授权、实际进程结算、其他独立用户要求及原任务的普通交付检查应保留。

核查：上述五项与原要求一致。删除的是应用内部的子 Agent 内容核对和补救申报协议，不是跨进程安全边界。负责人可以自行继续读取资料，不再填逐片补救表。未完成分片仅是汇总输入的状态事实；最终是否满足原要求仍由普通交付流程判断。已有明确错误码和触发条件，本次按机制删除处理，不另做保留该机制的多假设修补。

复用 `recordMapResult`、`acceptDiscussion`、普通 `DELIVER/CHECK_RESULT` 和现有恢复入口；无新增依赖或调度器。契约沿用 BT_Q36–Q49，并更新分片来源验收相关场景。先运行现有生产 XState 路径复现错误，再按场景、状态图、纯模型、接线的顺序实现。

## 全流程交接审查（追加需求）

原始要求：检查所有执行流程的上下游交接，消除同类审核死锁；如无必要取消系统检查；以来自下游最新的检查结论为准。

- HOF-01：当协助、评审、讨论或分片交给汇总时，系统应原样交接成功/部分成功结果，失败交付为空，历史失败仅作为下游输入，不永久否决后续有效结论。
- HOF-02：当负责人提交合法的当前版本交付时，系统应将来源声明和实际材料交给检查员，不在交接前逐条核对文档状态、回执和来源声明。
- HOF-03：当当前候选的检查员返回合法逐项结论时，系统应采用该结论，不因可选引用的目录匹配或逐字匹配再次要求检查或修订。
- HOF-04：当后续检查覆盖此前结论时，系统应在修订、展示、产物验证和发布中采用当前候选最新有效结论，历史记录不叠加否决权。
- HOF-05：当用户曾跳过执行步骤或旧讨论/评审失败，而当前候选检查通过时，系统应按当前结论发布；跳过和失败事实仍提供给检查员，不改写为成功。
- HOF-06：如果检查响应反复不符合必要协议，则系统应在一次技术补试后明确结束检查，不因全局预算设为最大而无限重复审核；网络故障预算保持原设置。
- HOF-07：当外部响应进入系统时，系统应继续验证协议结构、任务/目标/候选/尝试身份，并保留授权、停止、输入更新、产物版本、防数据丢失及未决物理效果边界。
- HOF-08（用户追加）：当下游检查发现交付问题时，检查员应在自己当前的工作中补救，并直接交付修正结果；不得驳回上游、重新派发负责人或形成交接环。无法补救时应在最终正文声明缺口并照常交付。
- HOF-09：如果必要的提交边界不满足，则系统应明确结算该错误，不再触发系统自动退回修订。工具调用和网络重试属于当前工作内部的执行，不构成角色交接回边；仍受授权、停止、预算和原配置的处理窗口约束。
- HOF-10（用户追加）：当下游仍有失败或未核实事项时，系统应将缺口写入最终交付正文并正常交付；不得因内容缺口阻止交付、回退上游或重新检查。完成交付不将缺口改写为已验证通过。
- HOF-11：当用户在已交付结果上明确重试仍失败或部分成功的协助时，系统应允许这次新的用户操作，保留旧交付和其他成员结果；不得因“已交付”状态永久禁止后续明确请求。系统自身不自动发起该操作。

最终解释：缺少要求的输出文件、无法取得原文、实际验证未通过也属于应声明的内容缺口，不能触发驳回。系统只引用本轮实际存在的文件；缺失/旧版本引用不产生虚假下载链接。损坏的协议、越权替换、停止与未决实际效果仍是必要执行边界。

下游补救取得的真实资料随同一工作持久化，网络补试可复用，不重新读取；实际测试失败时应提供原始诊断供下游补救，不能只留下错误码。原始来源声明也完整提供给模型，不再依赖已删除的宿主逐条核对。

HOF-08/09 覆盖此前“检查失败退回作者”的设计。检查工作拥有与当前配置相符的工具能力，宿主执行仍走原授权。检查员可返回完整修正稿和最终逐项结论；原稿保留为历史，新稿原子保存并发布。无法完成补救时明确结束，不把发现重新发回上游。用户要求的实际测试与工作区版本校验仍不可被文字结论绕过。

核查：覆盖所有角色交接中的内部内容审核，不授予旧消息跨任务调度权，不取消用户明确要求的实际测试执行和工作区版本校验。引用仅是检查员解释，不升级为宿主回执。保留必要协议并设置错误退出。复用检查工作、结果数组和技术补试，无新增调度机制。对应 BT_H201–H215 及原来源/引用场景。
