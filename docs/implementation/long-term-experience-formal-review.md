# 长期执行经验的形式化对应审查

审查基线为 `9c7eb7cd50ed3d54c5ff3acf6d54b67dafdac887`，受审源码为 `4af6b7f21cd3f1e7768927ec2310d0f8addf3298`。九份旧覆盖清单的全部指纹逐项与基线源码一致。[PR 首次 CI](https://github.com/kejun/squad/actions/runs/45024682640) 在运行 TLC 前触发源码漂移门禁。

## 源码对应

| 文件 | 变更与既有验证边界 |
| --- | --- |
| `src/engine.ts` | 终态快照、活动任务指针和经验待处理标记同事务提交。维护事务只更新会话经验字段，既有工作领取、消费许可、已发交付和复工意图继续由原事务负责。现有回放使用无会话经验的前缀。 |
| `src/execution-memory.ts` | 依据已保存的发布版本和宿主回执记录新经验。停止任务可反馈已采用的路线。读取历史时校验原始发布、结果和提取约定，供当前任务匹配。加入传递依赖漂移范围。 |
| `src/store.ts` | 会话记录新增可选字段，存储模式版本、写入及回滚实现沿用原路径。 |
| `src/task/context.ts` | 创建任务时复制可选经验输入，保证当前任务的匹配材料独立于会话索引的后续修改。 |
| `src/task/execution-memory.ts` | 分片复用需要来源、正文哈希和提取约定匹配。匹配路线需要当前配置，可信反证撤下建议。加入传递依赖漂移范围。 |
| `src/task/map-reduce.ts` | 匹配的分片在当前轮次直接结算并记录原发布和回执的引用。其余分片仍进入原队列、额度检查和交接。Shards 与现有交接回放使用无历史复用的前缀。 |
| `src/task/map-queue.ts` | 路线命中后，只为一个实际派发的分片带上建议，凭当前回执决定同批开放。沿用原派发资格、额度、工作意图和重试路径。现有回放前缀不含学习路线。 |
| `src/resource-acquisition.ts` | 正文版本匹配时，固定版本的交付可以引用当前轮次中已复用分片的原始证据。指定工作或操作 ID 的核对继续使用实际回执，要求当前获取的资源也继续走回执核对。既有回放不含正文版本声明。 |
| `src/task/result-aggregation.ts` | 归并输入附带复用来源，既有工作结果与证据身份沿用原字段。 |
| `src/task/execution-summary.ts` | 执行摘要增加已复用分片计数，既有发布事务和已结算分片状态沿用原路径。 |
| `src/task/tool-experience.ts` | 历史路线进入现有工具建议，实际执行仍由工作意图、目录与宿主许可控制。 |
| `src/types.ts` | 为已有任务、工作意图、分片和产物补充可选的经验及来源字段。 |
| `src/web/service.ts` | 通过已有本地运行时提供目录快照，经验读取依据当前目录版本。 |
| `team.config.ts` | 网页执行摘要配置默认启用经验；验证入口的显式前缀没有可复用的会话历史。 |

交接、交付、授权、协调、本地效果和宿主续办沿用各自的性质、有限域、回放与真实源码负对照。协调的 `CapacityDispatch` 负对照移到 `remaining > mapReduceCapacity(c)`，继续用真实派发断言检出容量判断失效。回放验证这些既有语义在原有限输入域内的对应关系。会话经验写入与恢复、路线反馈、分片选择和版本约束由 BT_Y181–BT_Y189 验收。真实模型开关对照覆盖公开资料的固定版本分片复用。
