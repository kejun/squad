## 集成验证

本地集成结果：三套 TypeScript 检查、43 文件/437 项回归、1187 个展开 Gherkin 用例（53435 步）、覆盖门禁、生产构建和真实 Linux 沙箱均通过。覆盖报告为 32 个 feature、477 定义、1209 展开；463 定义直接完整执行，14 定义/22 展开仍按原要求待验收。早期独立门禁夹具和新编号冲突被实际检查检出后修正，没有放宽断言或新增排除。

统一命令在仓库根目录执行；离线验证不使用供应方密钥。当前云环境仅注入模型密钥而无服务地址，因此本地命令使用 `env -u MODEL_API_KEY`，不读取或修改用户 `.env`。

```sh
npm run verify:local-sandbox
npm run check
npm run build
node --import tsx scripts/verify-local-crash.ts --negative-controls
node --import tsx scripts/verify-local-crash.ts
node --import tsx scripts/verify-sqlite-crash.ts
node tests/model-response-limit-negative.mjs
node .agents/skills/verify-squad/scripts/negative.mjs
```

本地原生沙箱还需 `socat`；本轮从官方 Debian 包提取至隔离的 `work/runtime/` 并加入命令 PATH。Chromium 使用 `/usr/bin/chromium`，字体为实际 Noto CJK。CI 在 Ubuntu 22.04 / Node 24.22.1 安装 bubblewrap、socat、ripgrep、fonts-noto-cjk 与固定 Playwright 1.62.1 的配套 Chromium。

浏览器应用以原生 TypeScript 启动，Python 3 监督器只回收自身创建的应用和后代。Linux subreaper 使沙箱能力探测的孤儿仍由本轮监督器回收；Doctor 和故障点记录真实 Node PID，应用组与监督器组均须消失。正常、SIGKILL、外层浏览器导入失败和离线产品负对照均验证该边界，早期未被监督的运行不冒充当前组清理证明。

集成时保留了两项开发门禁保护：Vitest 只发现仓库 `tests/`，避免临时工作树重复执行；只有包含真实浏览器契约的 Gherkin 集合才触发网页构建，使独立漏绑场景门禁继续检出 `undefined`。该门禁既有五项回归已通过，浏览器子进程仍强制核验构建证明。

CI 的 Complete verification 包含上述正向与负向入口，保留 `test-results/`、覆盖报告、截图/trace、HTTP/SQLite 观察和清理结果。Formal verification 继续执行四套完整检查。
