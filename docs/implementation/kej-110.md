## 方案与验收边界

1. **增量检查**：首检保持完整材料。相同目标、执行轮次、要求及冻结来源的已完成检查可作为修订基线；只在新内容能够逐行定位于旧候选或相关引文窗口时压缩。传送全部旧结论、要求、完整编辑（含删除）、文档身份及相关原文窗口，继续逐项独立判断，不能自动继承通过结论。任一前提缺失、增加未知事实、材料变化或无法获得显著压缩时沿用完整检查；冻结来源失效仍拒绝执行。不是任意文档重写都压缩，不承诺真实供应商固定延迟。
2. **来源绑定**：文档工作清单使用可选 `sourceItems`，每项保存 `sourceDocId`、`sourceEvidenceId`、`text`、`status`。机械预检仅接受完整成功 JSON CLI 回执中唯一文档的自身正文状态词，不能借邻文状态。宿主生成 D 编号；普通报告仍兼容。精确文字存在性不证明语义正确，仍需独立检查；未声明结构化工作项的散文不做通用自然语言推断。
3. **有界修订**：首次确定缺口少于3项时安排至多2次修订，3项及以上至多3次；后续缺口不扩大上限。普通检查分别至多3/4次，全周期技术补试仍至多1次。普通执行、checks、retries、截止时间与工程验证预留继续约束。无法核实不自动改稿。旧快照已经用掉唯一机会时保持旧周期上限。
4. **共享能力事实**：从同任务当前轮次和目标的已结算操作派生 discoverHost/listSkills 元数据、成功 CLI 参数和确定的沙箱不可用状态；不建立另一套缓存。记录绑定来源成员和操作，受权限、停止、大小与数量边界约束，运行时继续脱敏。不是宿主批准或另一个来源的采集凭证；并发首轮尚无事实时仍可能重复探测。
5. **分片**：保留最新主线的分片队列与独立并发上限。解释器默认充分使用 `min(独立来源数,maxPartitions)`，低于容量时说明语义合并理由；8篇/上限4分4片，8篇/上限8与并发4保留8片分波执行。提示不取代协议与运行时预算守卫。

中文契约：BT_F65–F83、BT_L113–L116、BT_Q34–Q35；未新增排除场景。状态入口：README「状态模型」及 docs/state-diagrams.md 的 KEJ-110 各节。已有 BT_F16/F17 明确最后复核额度，保留回归、机械缺口与停止等保护；BT_F27 中的次数断言按新有界预算调整。
