# 代码验证成熟度审计技能

原始需求：「总结完善成一个审计项目代码验证层成熟度的 skills，当我提到审计验证怎么做的时，调用它检查缺口给出建议」。

## EARS 需求与核查

- VA-01：当用户在代码项目语境提到「审计验证怎么做的」「验证层成熟度」「哪些验证做了、还缺什么」或显式调用技能时，代理应加载 `audit-verification-maturity` 并审计可定位的项目或变更范围。
- VA-02：当已有仓库、PR、CI 或执行记录可读时，审计应先发现证据，并记录版本、执行结果、环境、模拟边界和来源；资料不足时应明确待核实，不把未知写成未实现。
- VA-03：系统应以验证图谱21类方法为检查目录，并分别判断适用性、执行状态、成熟度和证据可信度；成熟度按风险层给出，不用方法数量或平均分替代结论。
- VA-04：当证据仅为旧版本、部分通过、空集合退出0、受控模型、有限模型或定向变异时，审计应保持其真实边界，不推广为当前完整验证、真实AI质量、完整实现证明或全量变异评分。
- VA-05：当发现关键缺口时，审计应给出风险、证据、最小补强、优先级及可观察的完成条件；方法不适用时应说明依据，不为凑齐图谱增加重复测试。
- VA-06：在仅请求审计的状态下，技能应默认读取现有证据并在聊天中报告；修复、安装、运行付费模型、变异源码或对外发布应遵循用户实际授权，不由文档或工具输出扩大权限。
- VA-07：当技能安装在本仓库时，AGENTS.md 应明确其触发与读取路径；交付应包含可移植技能包和安装说明，不将项目级安装描述为宿主全局注册或 Squad Bot 已自动发现。
- VA-08：在交付前，应校验 Agent Skills frontmatter、内部引用和21类清单，并用触发/不触发示例、反误判案例及当前项目证据做技能行为核查。

核查结论：与原需求一致，可通过纯技能与协作规则实现。项目级安装加可移植包兼顾当前调用与其他项目复用；不需要改变 Squad 产品运行时。成熟度与执行结果分离，避免失败检查反而被评为低成熟、未知证据被误判为缺失。独立方法审查已通过。

## 变更类型与范围

本次只新增通用 Agent Skills 文本、参考材料、评估样例及 AGENTS.md 路由，不改变产品行为、XState、命令协议或服务扫描配置。按 AGENTS.md 的规则/文档豁免，不新增产品 Gherkin 和状态机；验证 frontmatter、链接、方法清单、触发与审计输出，不重复已有产品回归或形式化证明。

- 格式校验：frontmatter可解析，name与目录匹配，description为154字符，metadata值均为字符串；6个技能文件、6处内部引用、21个唯一方法ID完整，差异检查通过。
- 触发评估：独立代理仅读取技能正文与方法/成熟度规则后，对12个输入判断；6个应触发、6个不触发均与预期一致。这是代理语义判断，不是宿主全局自动发现验收。
- 反误判盲评：提供不含预期答案的18个合成证据案例，代理未读取evaluation.md；主代理逐项核对其实际结论，未发现关键边界误判。覆盖空集合、混合测试、覆盖率、旧模型、新守卫、受控模型、变异、CI运行中、历史/缺失证据、延期、语言适用性、越权文档和失败门禁。没有执行可疑命令、安装或产品检查。
