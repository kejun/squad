# 模型服务错误的明确决定

原始要求：LLM 服务返回 403 / 400 等错误时显示相应消息，弹出层，用户可以“跳过”和“停止任务”。参考用户提供的 403 截图：现有通用门错误地展示回复框和续窗按钮，分片错误还可能未进入人类门。

## EARS 与核查

- MERR-01：当模型服务返回不可自动重试的 HTTP 4xx 错误时，系统应显示 HTTP 状态及脱敏的提供方错误信息，并持久保存模型服务错误门；适用于负责人、分片和检查等模型工作。
- MERR-02：在模型服务错误门打开时，网页应自动弹出“模型服务调用失败”提示，提供“跳过”和“停止任务”；不应要求回复文本、续窗或先核对执行。
- MERR-03：当用户跳过失败分片时，系统应仅跳过该分片并保留其他已完成结果；非分片工作没有可继续的结果时，应保留已有成果并以不完整结果结束，不得原样重试相同错误请求。
- MERR-04：当用户停止任务时，系统应停止整个任务，保留已有成果；关闭浮层、刷新或恢复不得代答、清除错误或重复发起失败请求。
- MERR-05：如果错误是已有的 408、429、5xx 网络类瞬态故障，则系统应保留既有预算内的重试规则；删除后的会话及旧轮次回调不得重新开启门。

核查：保留用户明确的消息、浮层和两项操作。复用既有人类门、决策 API 和停止路径；新增错误 cause 与结构化失败码，不新增调度器。错误信息脱敏，避免把凭据或整段请求正文写入错误提示。上下文越界也属于需明确处理的模型错误；原处理窗口到期仍走续窗门，二者不混用。场景 BT_Y168–Y172。
