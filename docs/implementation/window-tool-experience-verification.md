## 真实恢复及权限边界

六个活动阶段均执行到期、续窗、交付、检查、complete 的真实模型轨迹；8组真实 Engine 路径另核对已有必需门的到期唤醒、恢复与第二次续窗，另验证未开始分片、已领取解析、未完成协助、已保存答复、未知物理效果与通用 CONTINUE 入口。已有必需门仍会按原硬期限唤醒一次并记录失败，保存后不按旧期限反复唤醒。续窗保留 epoch、原成果、计费、分片及回执，旧宿主会话授权撤销，未知效果仍须独立结算。跳过旧命令只省略其范围；结束窗口才冻结任务。

stdin 输入是工作区文件的私有只读字节快照。固定检查只使用运行时脱敏后保存的实际 executable/argv/cwd/environmentHash 和 stdin 指纹；内部原动作快照不进入模型材料。普通 owner 的 `validationInputsChanged` 为 null，不把未经测量的 false 当成未修改证明。相同路径修正输入字节后可重试，相同实测输入和环境仍受重复失败限制；固定验证命令不能附加 stdin。

旧固定 CLI 检查引用没有新增的调用身份快照时，会明确拒绝 `CHECK_EVIDENCE_CHANGED`。需要重新提交候选形成新固定边界，不会补造旧输入指纹或沿用为已验证的新证据。这是升级中的保证边界变化。

## 实机证据与适用范围

自动目录在本机发现 1671 个命令，完整原始目录约 783KB、扫描约 1.3 秒。带两环境观测与接口的完整模型请求约 2.54MB；首个真实模型请求使用约 71 万输入 token。服务通过后台快照避免每次决策扫描，保留全部条目；全量策略仍有实际上下文成本。包级摘要、资料来源、未知用途与同名 wrapper 的不同说明均保留，不能借其他安装位置的 man 说明推断能力。

使用用户提供的 `deepseek-v4.1-flash` 与 API 地址运行了真实模型 → WorkRunner → SQLite → 原生沙盒 → tesseract → 固定检查。最终应用源码（C3，应用输入与C4完全相同）的任务 53,558ms、5 次模型请求；模型先用 ls/file 核对输入，随后通过工作区 stdin 真实识别，输出 `HELLO`，保存 OCR.md 并以 complete 结束。三条命令全部成功，无错误工具试探。完整请求、响应、回执、源码指纹及凭据扫描记录保留在 `/workspace/work/squad-window-experience/live-c3/`。较早C1源码另一次完整任务为34,751ms/4请求/2次OCR复核，原件保留在 `live-final/`。这些是具体任务的结果，不是最少调用或普遍准确率声明。

工具选择准确性须与发现完整性分开：本轮只读目录审计的1671条中，1559条有静态资料，但1553条来自包摘要；自动条目的场景字段只有三种通用句式，未提取工具专属的输入输出、SYNOPSIS、子命令或参数前提。104条共用GNU core utilities摘要，165条共用TeX Live摘要。当前可证明不再漏掉旧上限之外的工具、保留环境与资料来源、无需先失败再选宿主；不能据此声称模型选型准确率提高。原本机语雀场景未在这里实测。详细只读统计保留在外部`ci-final/catalog-accuracy-audit.json`与`catalog-accuracy-assessment.md`。

初次真实任务的 partial 原件保留在相邻 `live/`。当时固定材料缺少实际调用和输入身份，且测试配置输出预算为 6000 token；后续完整任务补齐证据并使用16000 token。因此这不是单一因素的准确率或因果性能研究，也不声称所有 OCR 工具都支持 stdin。内置具体例子只对应本轮实际运行的 tesseract。

Cucumber额外保存标准message流，使中断时仍保留精确失败用例。没有排除新失败或删除旧保护；Cucumber、检查执行器及CI的执行超时保持原值。

C5远程CI的7项作业成功，Complete失败于L84两例、Q47、Q48、Y60的原5000ms步骤限制，而非20分钟job超时。定位为两个受控非目录夹具仍扫描机器全PATH：preparation每个崩溃/重启child分别扫描，map恢复每轮请求还携带完整目录。单变量对照中，LocalRuntime自动创建约975–1291ms，显式空目录约2ms。L84在明确标记的1CPU/双驱动压力下，原六次7360–8520ms全红；仅fixture显式空目录后2403–2758ms全绿，全部原真实SIGKILL/重启及清理断言保留。map本机未复现5秒红，自动组约3.3–4.2秒，空目录组约1.5–2秒；CI原失败证据与这个局限均保留。
