## 先行反例与产品修复

1. 跨群发送使用一个全局sendIdentity。A已经提交但丢回执后，B成功发送清掉A身份，A重试产生另一UUID和第二条消息。改为每个room保存身份，只清除成功的目标room。BT_U20的两种真实浏览器输入验证原命令重放。
2. 技能包rename成功、递归只读准备前宿主被SIGKILL。新实例复用完整包却跳过只读目录准备。内容校验通过的既有包重新执行可重复的目录权限准备。
3. 隔离副本marker成功、scratch准备前宿主被SIGKILL。新实例复用marker却向backend交付缺少HOME/TMPDIR的副本。合法marker复用前补齐scratch。
4. WebService启动恢复第一条操作时关闭，第一条返回后仍开始第二条reconcile。在每次reconcile前检查closing。真实屏障保持第一条正在运行，由公开close触发并核对第二条从未启动。

准备期原7案保留5绿2红，修复后通过；新增公开check副本案证明execute原有晚准备已补齐全部4输出目录，不为此增加重复产品修复。先行中文场景、宿主流程/状态图和真实XState模型门槛均在相应源修改之前完成；文件/浏览器/生命周期接线由各自真实边界验证，未塞入新的业务XState state。

## 验证准入与证据

新增辅助驱动为事务存储、真实FS/进程/HTTP/浏览器的集成验证与有限序列探索，不以私有Map、手写context或mock期望结果代替产品。Gherkin提供直接业务验收；每个模型逐边从真实公共入口构造一个代表前缀，在MemoryStore和SQLite各执行一次。生成序列补充BDD不能枚举的顺序，断言独立的用户后果与持久领域不变量，不复制reducer条件作为oracle。

每个模型检查包含固定TLC JAR、全有限图探索、独立进度性质、可达性见证、隔离真实代码负对照、原版恢复复验、源码未变和独立证据读回。代码变体继续使用原模型图，不能以哈希门禁或导入失败算检出。新读回检查要求原始TLC完成、活性与实际统计、全边JSONL和目标投影、真实失败JSON/diff、完整见证集合。另有重算manifest后删负对照、删边和原日志破坏控制，防止只相信自报verified。命令和结果见[形式化入口](../formal-verification.md)、各技能references及[本轮机器记录](kej-107-108-evidence.json)。

CI在原四技能完整门禁外增加五个独立composition作业；delivery原入口已经包含三新slice。完整测试作业加入网页/服务源码故障检出、准备与模型会话控制/读回。保留reports原始证据14天。`npm run check`仍完整执行原回归、所有Gherkin和规格覆盖，生产build单独检查。

## 保证边界

这是有限抽象穷举和每条边的一条代表公共前缀对应，不是TypeScript全程序证明；同一投影的所有具体历史没有全部重放。各模型有自己的固定人数、次数和故障预算，不把六技能拼成全系统组合证明。公平性仅按各cfg声明，不承诺用户必然审批、供应商必然成功或未知效果终会得到确认。

本地效果图保守合并prepared与可能已spawn而无确定回执；真实spawn/SIGKILL由独立7接线案例补证。OneStart只针对该单逻辑启动域，不是任意OS命令恰好一次。SQLite事务原子性是模型假设；真实COMMIT前后杀进程也不是硬件断电证明。取消讨论的ended+未知旧物理工作由coordination另验：room恢复可能按既有selector无提交；必须保持占用，可信旧回执才能结算，不能声称自动释放。

外部模型质量、真实供应商/网络可靠性、任意恶意磁盘改写、跨机器锁以及无限故障不在本次结论。所有扩展的精确初态、动作原子性、范围、公平性和排除项以各技能对应文档与本轮捕获的checker输入为准。
