# 跨会话资源等待与宿主授权

原始反馈：已停止旧任务的未决宿主操作仍持锁；新任务的四条 `yuque --help` 保持 queued，当前会话没有阻塞核对或授权提示，监督误将父工作 inflight 当作有效执行。

## 需求核查（EARS）

- R-W01：当本地操作因真实资源冲突被拒绝领取时，系统应保存该操作尚未启动的资源等待事实，并在当前任务显示等待资源，不把它计为有效执行。
- R-W02：在当前操作被旧任务未决效果阻塞时，系统应在当前会话显示实际冲突来源及原操作核对入口；核对必须指向来源会话、任务、工作和操作。
- R-W03：如果未决效果仍未可信结算，则系统应保持资源隔离，不通过关闭提示、停止新任务、普通回复或错误核对释放旧锁，也不得把 queued 操作展示为已经产生宿主授权申请。
- R-W04：当一个阻塞操作可信结算时，系统应唤醒原资源等待者；仍有其他冲突时继续等待，全部冲突消除后按原流程提出新命令自己的精确授权，批准前不得启动。
- R-W05：在刷新、重启、并行请求和普通短时竞争时，系统应保留可重建的真实等待状态，只显示实际冲突，不把兼容读或无关资源列为阻塞。
- R-W06：当资源等待耗尽已有自动处理窗口时，系统应如实交付不完整结果，并保留旧操作核对入口；等待或资源唤醒不得暗中延长窗口。
- R-W07：当八份受登录保护资料被拆为八个分片、四名成员在正文获取失败后改用 CLI 且均被旧任务资源阻塞时，系统应在当前会话显示资源等待与核对入口，队列不得冒充实际执行；未取得正文不得算资料获取成功，也不得等到十五分钟部分结束才暴露该阻塞。
- R-W08：当协调者作出调度判断时，系统应提供所有会话、任务及成员的最新执行状态、操作是否实际启动、资源持有与等待依赖、待授权、未决核对及原处理窗口；该视图不得仅限当前任务或使用创建协调意图时的旧快照。
- R-W09：如果协调者读取全局执行视图，则系统应将其作为只读观察，不授予批准宿主、核销未知效果、修改其他任务或绕过租约的权限；每次实际模型请求重新读取，状态变化后下一次请求应可见。

R-W04 结算入口包括人类核对、后台回执恢复以及归档删除准备期间的原操作核对。三者共用资源通知；删除记录成功不等于等待者已经被唤醒。当前目标改写并取消旧依赖时，不再导入不相关的跨会话核对门；停止或到期仍保留实际未决效果的核对入口。

R-W08/R-W09 来自用户明确补充“协调者要全部可见”。交付为协调模型请求中的完整全局执行元数据视图，沿用现有授权和调度协议，不复制密钥配置或文档正文，不通过截断或只保留当前会话来伪装全部可见。视图是观察，不把未启动或待授权误称为实际执行。

以上是现场缺陷的最小修复范围；核查通过。现有租约、授权、核对摘要与原窗口约束复用，不新增模型权限或远端服务。新任务没有授权提示的原因是尚未到达授权阶段，而非已有授权被 UI 丢弃。

## 归档删除反馈补充（BT_Y119）

原始反馈：删除归档会话后列表没有变化，看起来没有删除成功。现有删除服务与等待未决操作验收通过，但非选中会话的删除请求受理后弹窗立即关闭，列表没有明确阶段反馈；原浏览器场景主动再次打开状态才检查，遗漏了受理后的连续可见性。

- R-D01：当用户确认删除归档会话而服务只返回准备、等待或暂停状态时，网页应持续显示该目标的真实删除进度和适用的处理入口，不能把受理显示成已删除或无反馈关闭。
- R-D02：当目标已确认删除时，列表应移除该目标，刷新后仍不存在；等待期间关闭提示或切换会话不应删除其他目标或丢失可重新打开的进度。

核查通过；复用既有 roomDeletionMachine，不新增状态、权限或删除范围。状态模型不变，UI 仅根据已持久阶段展示；已有 deletionMemoryServiceAcceptance、deletionPhaseAcceptance(ended/partial)、deletionOperationAcceptance(uncertain) 已通过，作为具体 UI 修复前的模型/服务复验，不把它们当作新浏览器场景已通过。
