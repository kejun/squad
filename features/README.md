# 验收场景

可执行的中文 Gherkin 是产品行为的唯一验收契约。新增场景默认进入 `npm run test:bdd`，缺少步骤绑定会令检查失败。`@BT_*` 身份必须唯一；场景大纲的每个例子均单独执行。

当前尚不能自动验收的范围在 `acceptance-gaps.json` 中逐项登记原因及场景编号，并在对应场景或功能上添加同名标签。排除项也必须进入覆盖报告；不得为了让检查通过而删除场景或随意扩充排除标签。Pi Durable 的原始要求保持不变，本地 SQLite 回归不冒充其验收。

报告区分直接执行的 Gherkin、仅关联的回归断言和明确待验收项。更新功能遵循根目录 `AGENTS.md` 的顺序。

单测只补充场景无法清楚表达的验证形态，准入和评审记录遵循根目录 `AGENTS.md`。存量测试的逐项承接、直接执行及故障检出证据见 [KEJ-100 测试审计](../docs/testing/kej-100/README.md)；既有验收缺口继续如实登记。

## 场景粒度

遵循根目录 `AGENTS.md` 的「Gherkin 的职责与粒度」：场景保留可观察行为和约束，颜色、字号、装饰、几何值与选择器由样式规范和专门检查承接。交互场景中的视窗、距离和断点样本放在步骤夹具或低层测试中；键盘可操作、尺寸边界、取消、持久化与恢复等行为仍须直接执行。业务额度、协议值等决定行为的数字不在此次清理范围。
